# The optimizer

Choices made in the optimizer. They describe the inside of the compiler.
`docs/decisions.md` holds what a reader of the language or a user of the
tools can observe.

- A round of `optimize_function` runs constant folding, the peephole rules, scalar replacement, store forwarding, copy propagation and dead code elimination, in that order. The rounds repeat per function until nothing changes, and the temporaries are renumbered after them. The peephole rules run before copy propagation, and forwarding runs before propagation, so the copy it leaves goes in the same round. Block merging runs once before the first round. A dropped dev-mode check leaves a jump into the block that follows it, and the rule that fuses `t = op` with `x = copy t` needs the two adjacent. A round of propagation between them gives `t` a second use, and the pair never fuses. After the functions, the optimizer removes functions and globals that the entries cannot reach, which `reach.c` marks. The entries are `main` of the main module, or every function of that module when it has no `main`. Every exported function and datum and the constructor of the patterns are entries too, and every function of a host of plugins.
- `split_slots` is scalar replacement. A struct or class local whose address never leaves the function becomes one temporary per field. The address escapes when `&` is taken of it or of a field, and when it passes as a pointer or goes into another object. It escapes when its temporary is written a second time. `self` always escapes.
- `forward_stores` turns a second load of an address in one block into a copy of the value last stored to it or loaded from it. The optimizer has no alias analysis, so a call, an atomic operation or a store to another address ends what it remembers.
- Folding leaves division by zero, `MIN / -1`, shifts by the width or more and out-of-range float to integer conversions in the IR. Folding an `f32` computes in C `float`.
- Copy propagation replaces uses of `x = copy v` inside a block until `x` or `v` changes. Across blocks it needs a single definition of `x` and a constant, an unassigned parameter, or a single definition of `v` earlier in the same block.
- Peephole rules: constants move to the right of commutative operations. `x + 0`, `x - 0`, `x | 0`, `x ^ 0`, shifts by 0, `x * 1` and `x / 1` become `x`. `x * 0` and `x & 0` become 0, and `x & -1` becomes `x`. `x * 2^k` becomes `x << k`, `x udiv 2^k` becomes `x >> k` and `x urem 2^k` becomes `x & (2^k - 1)`. `t = op; x = copy t` becomes `x = op` when `t` has no other use. A branch with two equal targets becomes a jump. A jump to a block that only jumps goes to the final block.
- Dead code elimination removes pure instructions without a used result and definitions that their block overwrites before any use. It removes blocks that no path reaches and merges a block into its only predecessor when that predecessor jumps to it.
- The verifier checks definite assignment: every path from the entry to a use of a temporary passes a definition. Integer constants in the IR keep only the bits of their type.
