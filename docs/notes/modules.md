# Modules and library files

Choices made for modules and library files. They describe the inside of the compiler.
`docs/decisions.md` holds what a reader of the language or a user of the
tools can observe.

- Library format: magic `ANTL`, the version, little-endian integers of fixed width, strings as a u32 length and bytes, floats as IEEE 754 bits. Enum values are stored as bytes, and `_Static_assert` checks guard them. All function signatures precede all bodies. `put_inst` of `antl_write.c` writes an instruction as a record of 49 bytes: the operation, the type, the line, the result, three operands of 10 bytes each, the type of an access and the field. A load or a store of an aggregate adds the member, and the count of the arguments and the arguments of 10 bytes each follow.
- An IR function of another module is an `extern fn` with a module name, as in `extern fn scale.scale(i64) -> i64`. Loading maps it to the loaded definition.
- The reader checks every count against the bytes left and every index against its table. A damaged file reports `is damaged at byte N`. Other messages: `is not a library file`, `has format version N, and antic reads version M`, `needs module`, `needs struct`, `needs module of M.T`, `needs generic M.G`, `needs function M.F` and `defines M.F, which another library defines`. `needs function M.F`, or `M.C.f` for a function of a class, names a function that the code or a generic of a file calls and the file of its module lacks, by "Answers of 2026-11-12" in `docs/decisions.md`. `` needs function `M.F` as `S`, and the library holds it as `T` `` names a function that the file calls by its name, or that a generic of the file calls, whose signature the later file changed. A signature is written as a type of a function without `self`, such as `fn(int) -> f64 may fail`, with the module of every struct in it.
- The table reads. A call through the table of a class names the descriptor and the slot alone, so the last section of the IR of a library file lists each function that the file reads from the table of a class of another module. Each record holds the module and the name of the class, the name of the function, the count of its parameters with `self` and the slot. Lowering adds one record per distinct read, at a call through the table, at a bound function and at the thunk of a body reached through an interface, in `lower_note_table_read` of `src/antic/lower_desc.c`. The root, a type the compiler declares and a copy of a generic take none. The reader finds the class in the file of its module, lays out its table with `sema_table_of` and looks for the entry of the same name and count. A missing class is `needs struct M.C`, a missing function `needs function M.C.f`, and a function at another slot `` calls `M.C.f` at slot N of its table, and the library holds it at slot K ``. Each record carries the signature of the entry as well, and an entry with another signature is `` calls `M.C.f` as `S`, and the library holds it as `T` ``. The records came in with format version 95, by the second answer of "Answers of 2026-11-12" in `docs/decisions.md`.
- The table writes. A class of a library file may have a class of another module in its chain. Its table is then laid out against the table of that class, and so is an interface sub-object of such a class. After the reads, the IR of a library file lists one record per table it writes against a class of another module. Each record holds the qualified name of the class whose table the file writes. It holds the module and the name of the class it was laid out against. It then holds the name and the count of parameters with `self` of each entry of that class, in order. That class is the nearest class of another module in the chain of the class. For a sub-object it is the nearest in the chain of the interface. The root and a type the compiler declares take none. Lowering adds the records in `lower_class_table` and `lower_interface_table` of `src/antic/lower_desc.c`. The reader finds the class in the later file of its module. It lays out its table with `sema_table_of` and compares the entries in order. A missing class is `needs struct M.C`, and a missing entry `needs function M.C.f`. An entry at another slot is `` fills the table of `X` with `M.C.f` at slot N, and the library holds it at slot K ``. An entry the file lacks is `` fills the table of `X` without `M.C.g`, and the library holds it at slot K ``. Each entry carries its signature as well, and an entry with another signature is `` fills the table of `X` with `M.C.f` as `S`, and the library holds it as `T` ``. For a copy the signature is that of the entry of the generic. The records came in with format version 96, by "Answers of 2026-11-12" in `docs/decisions.md`.
- Copies of generics. A library file holds the code and the table of each copy of a generic of another module that it uses. The program keeps the first copy of each that it reads. The reads and the writes of the table of such a copy take records as those of a class do. A record names the generic in place of the class. The reader then lays out the table of the generic of the later file. A copy takes the functions of its generic, so its table and the generic's hold the same entries. A file that reads the table of a copy writes the copy as well, so the record of that table covers the read. A copy of a generic function stands in no table. `read_signature` of `src/antic/antl_read_ir.c` refuses a copy whose generic the later file lacks with `needs generic M.G`.
- The digests of generics. The reader of a library file hashes the declaration and the trees of each generic it reads, with every type named by its qualified name and every symbol of another item by its record, so the digest follows the generic and not the indices of the file. The doc text stays out. After the table writes, the IR of a library file lists one record per generic of another module that it copied: the module, the name, whether it is a function and the digest the file was built against. The reader refuses a later tree with another digest with `` holds a copy of `M.G` made from another tree than the library holds ``, and refuses a generic the later file lacks as `needs generic` and `needs struct` do. Every copy a program reads is then made from the tree the program holds. The signatures and the digests came in with format version 97, by the third answer of "Answers of 2026-11-12" in `docs/decisions.md`.
- Import errors: `` `main` cannot import itself ``, `` `b` depends on `main`, so the import forms a cycle ``, `` `geometry` has no public item `x` ``, `` `geometry` has no public struct `X` ``, `` `geometry` is a module, not a value ``.
- The type table, the externs and the trees of the generics are described in "Library files" of `docs/notes/generics.md`.
- `antl_verify.c` holds the verifier of library files. It holds each tree the reader built to the rules the checker makes true of a tree, and a tree that breaks one is damaged. The DESIGN at its start lists the rules. "Sanitizers" in `docs/notes/hosts-and-harness.md` gives the stack its walk takes.
