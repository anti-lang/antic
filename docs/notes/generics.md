# Generics

Choices made for the syntax of generics in each pass. They describe the
inside of the compiler. `docs/decisions.md` holds what a reader of the
language or a user of the tools can observe, under "Generics and
collections".

- The lexer reads `constraint` and `type` as keywords, `TOKEN_CONSTRAINT` and `TOKEN_TYPE`. Both stand after every earlier kind, so no value the library file stores moves, and the format version is 61 for the longer token table.
- The parser reads a list of type parameters after the name of a function, a struct, a class or a variant. A function of a class body takes one as well. Each is a `struct type_param` with its name, its constraints as `struct constraint_ref` and the mark of `N: int`.
- A type reads `<` after its name as type arguments, held in `args` of the `TYPEX_NAMED`. An integer literal among them is a `TYPEX_CONST` that holds the literal in `length`. A base after `inherits` keeps its arguments in `base_args`.
- `>>` closes two lists. The inner list takes the first `>` and sets `half` of the parser without moving past the token, and the outer list takes the second and moves. `angles` counts the open lists, and a `>>` with one list open is refused.
- In an expression `generic_end` scans the tokens from `<` as a list of types without building anything, with the same rule for `>>`. A list whose next token is `(`, `.` or `{` makes the name an `EXPR_NAME`, an `EXPR_FIELD` or an `EXPR_STRUCT_LIT` with `type_args`. `Result<int, str>.Ok { }` and `geo.Pair<int, str> { }` are literals with their arguments.
- `constraint Name = a + b;` is `ITEM_CONSTRAINT` with its list in `constraints`, and `type Name = T;` is `ITEM_TYPE` with its type in `type`.
- The checker gives each type parameter a `TYPE_PARAM` of its own and a symbol. A type parameter is a `SYMBOL_STRUCT` whose type is the parameter, and `N: int` is a `SYMBOL_CONST` of type `int` whose value is a `SYMBOLIC_PARAM`, so `[N]T` is an array with a symbolic length. `sema_module_find` looks the parameters up first, in the signature being resolved, the function and the functions around an anonymous one, then the classes around the code.
- A `TYPE_PARAM` holds the hooks its constraints give, one bit per entry of the hook table in `sema_generic.c`, and the interfaces. A `constraint` holds its set in a `TYPE_PARAM` of its own, resolved on its first use with the cycle check of `EVAL_BUSY`.
- An operator whose operand is a type parameter checks the hook in `param_binary` of `sema_expr.c` and `check_unary`, before the struct rules read the operator. A call on a value of a type parameter reaches the interface of its constraints that declares the function, as a pointer to that interface.
- A copy of a generic struct, class or variant is a type of the kind of its generic, named as a program writes it, `Pair<int, str>`. It holds the generic and its arguments. The copies of one generic form a list on it, so two uses with the same arguments give one type. The fields, the base and the cases of a copy are those of the generic with the arguments in place. They are filled once the generic has its own. A copy whose arguments are the parameters of its generic is the generic, as `List<T>` is in the body of `List`.
- A copy shares the members of its generic, whose types name the parameters. `sema_member_type` puts the arguments of the copy into the type of a member where a call, a `construct` or the check of a replacement reads it.
- A copy may be named in a field or a signature before the functions have their types. Its arguments are checked against the constraints after `check_signatures`, since an `operator fn` gives a hook. Every later check runs where the use stands.
- `sema_check_call` carries a `struct generic_call` past the rewrites of a method call. It holds the arguments written after the callee, the class before `.` or the type of the receiver, and a slot per argument. `sema_generic_call` binds the parameters of the class from the copy and those written after the name. The rest come from the arguments in order. An argument whose parameter names an unbound parameter is checked without a type expected. The two types are unified, and the slot keeps the result, so the argument is checked once.
- `Number` has no item. `add_constraint` gives its six hooks to a name `Number` that finds nothing in the module, as `sema_resolve_type` gives `Regex` to a type of that name.
- `sema_iterate` hands a `TYPE_PARAM` to `sema_param_iterate`, and `e[i]` and `e[i] = v` hand one to `sema_param_index`. Neither rewrites the node into a hook call, since lowering never reads the body of a generic. The value each gives is a `TYPE_PARAM` without a `param`, cached in `walked` and `indexed` of the parameter, and `param_lacks` words a refusal on one without the fix of adding a constraint.
- `sema_strip_generics` takes the generics out of the module before a library file or lowering reads it. The functions of a class body with parameters of their own, the types nested in a generic class, every `type` and every `constraint` go with them. The copies stay, since none of them is generic.
- `anti fmt` marks the angle brackets of a list by the rules of the parser and writes them without spaces. It marks a list after the name of a declaration and a list in a type. In an expression it follows the rule of C#. A list is a bracket to the formatter, so a `:` or a `,` inside one ends nothing.
- The tests: `dump_ast_generics_syntax` pins the tree of each form of the parser, `listing_generics.types` the types the checker gives, with the inferred arguments. `listing_error_generics`, `listing_error_generic_syntax` and `listing_error_generic_copies` pin the refusals. `listing_constraints.types` and `listing_error_constraints` pin what the constraints give and refuse, and `program_generic_unused` runs a program whose generics nothing uses.

## The copies

- The driver sets `compile_copies` of the module on a build past the front end that is no `--dump-types`. `sema_check` then runs `sema_compile_copies` of `sema_copies.c` last, while the scopes of the module still stand.
- `sema_generic_call` records the arguments of the copy a call reaches on the call, in `copy_args` and `copy_values`. Those of the class come first, then those of the function. Each is a type or a constant, and may name the parameters of the generic around the call.
- The pass walks the code that is not generic in place and names the copy at each call of a generic. A copy of a function is an item cloned from the generic with its own symbol, `max<int>`. A copy of a type gets an item cloned from its generic, and a clone of each function member, `List<int>.push`. The clones replace the members of the copy type, so `sema_find_member`, the tables and `construct` all reach them. A function with type parameters of its own keeps the member of the generic and is refused where it is called.
- The body of each clone comes from a list of work, filled as calls and types name new copies. A copy type that the checker made and no call reached still gets its item, so its table is complete. The pass runs until the list is empty and every concrete copy of a generic of the module has its item.
- The clone copies every node once, through a map of pointers, so a node that two places share stays shared and `call.out` names its own call. Locals, parameters, local constants and anonymous functions get symbols of their own. A constant parameter `N` is a constant whose value is `SYMBOLIC_PARAM`, and its clone takes the argument as its value.
- `ty` puts the arguments into every type through `sema_subst`. A type that still names a parameter refuses the copy, which keeps a form the pass does not know out of lowering.
- An operator, a `for` and `e[i]` on a value of a type parameter are open nodes. The clone makes the operands first and marks each `prechecked`, and `sema_check_expr` then gives a prechecked node its type as it stands. The node itself is checked again with the types of the arguments. The checker rewrites it as it would in written code, so a struct operator becomes the call of its `operator fn` and a hook becomes its call. `e[i] = v` goes through `sema_set_index`. The value a walk gives, `C.value`, and the value `e[i]` reads, `C.index`, join the map of the copy with the types found there.
- A call of a function of an interface of the constraints leaves the receiver typed as a pointer to the interface. `param_type` of the receiver keeps the type it had. The copy gives the receiver the type of the argument and converts it with `sema_require`, which writes `to_iface`. A value takes its address first.
- A `construct` that a literal runs records no arguments of its copy. The copy of its class then comes from the object it builds or from the receiver.
- A field of a copy names the copy as its `home`, so its symbols of reach and thunks are its own.
- `type_symbol_name` writes the name of a copy with the arguments qualified, and lowering names every symbol of a type with it. `mangle` writes each byte of a name outside letters, digits, `_` and `.` as `$` and two hex digits. `symbolize`, `anti symbols resolve` and the map read the escapes back, and the debug information names the copy as the program writes it, as `docs/notes/symbols.md` and `docs/notes/debug.md` say.
- In a dev object `emit` marks a function or a global whose name holds `<` as link-once: `.weak` on ELF, `.weak_definition` on Mach-O, and a section of its own with `discard` on COFF, closed after it. `asm_copies_<target>` checks the line on every target.
- `merge_copies` of `whole.c` runs after the devirtualisation of a release build. It compares every pair of copies and marks the later one as served by the earlier. It repeats until nothing changes, since a merge can make two callers identical. Then every call, table entry, relocation and init names the copy that stands for it, and the optimizer drops the rest.
- The tests: `programs/generic_copies.anti` in release and as `program_generic_copies_dev`, `listing_copies_merge.opt` and `listing_copies_merge.dev.opt`, `asm_copies_<target>` and `listing_error_generic_copies`.
