## Tests first

- S30, the new test `files_oom`. `files_oom_tests` asks each helper for
  `SIZE_MAX / 4` bytes and expects status 70 and the message. Before the
  fix `files_array` came back with NULL (`s13-oom-red.log`). The program
  tells AddressSanitizer to answer NULL, so the test runs in both
  sanitizer trees.
- S31, `anti_bind_ast_malformed`. The stand-in clang writes markers of
  4294967296, 99999999999999999999 and `INT64_MAX`. Before the fix none
  was refused (`s13-bind-red.log`). `anti_bind_clang_malformed` binds
  declarations after `#line 2147483647`, the case that overflowed on
  Windows, which the host's 64-bit `long` cannot show.
- S32, `anti_bind_clang_malformed` binds `enum Wide : unsigned long long
  { WIDE_TOP = 0x7fffffffffffffff, WIDE_NEXT }`. UBSan stopped it at the
  sum before the fix (`s13-ubsan-bind-red.log`). The host wraps and
  showed nothing.
- S34, `anti_build_deps` writes `-9223372036000000000` into the stamp,
  changes the index of the repository and builds again. Before the fix
  the cached index kept the old revision (`s13-deps-red.log`).

## Found and left

`bind --clang` compares two kinds of line. The reader of `clang -E` counts
presumed lines, which a `#line` directive moves. The AST gives the
physical line in `line` and the presumed one in `presumedLine`, and
`track` reads `line` alone. After a `#line`, `pack_at` looks a struct up
among packs counted in another numbering. It can then refuse a struct
packed to one byte, or take a struct packed to two for one packed to one,
which binds a wrong layout. A header with `#line 2147483647`, then
`#pragma pack(push, 2)` and a struct, showed the lookup miss. clang writes
`presumedLine` only where it differs from the location before it, so the
fix needs a rule for the locations without it. The audit does not name
the defect, and the step leaves it for a later one.
