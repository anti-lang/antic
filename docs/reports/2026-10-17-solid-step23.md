# Solid: step 23, build files, the tool list and the triples

The step fixed the three findings of step 23 of "Fix steps" in
`docs/audit/summary.md`: M326, M341 and M342. No later step names any
of them, and no decision of "Decisions of 2026-10-11" bears on them. It
ran in one session on 2026-10-17 from `fa7f33ea`. The logs lie in
`build/drive/logs/`, under names that start with `s23-`.

## Findings closed

Each still stood at `fa7f33ea`, found again by its code, and each got a
test that failed before its fix.

| Finding | Commit | Cause and remedy |
|---|---|---|
| M326 | `c470bafc` | The target `llvm_tools`, the only producer of `bin/` of the runtime archive, stood in `tests/CMakeLists.txt` inside `if(ANTIC_LLVM_MC)` and took its directory from the path of llvm-mc. It stands in the root file beside the copies of the sanitizer runtimes and reads `ANTIC_LLVM_DIR`. The test `llvm_tools_root` holds it. |
| M341 | `29873529` | `tools/check-llvm.cmake` checked nine names and copied eleven of lists of its own, and a second check in `tools/pinned-tools.cmake` read the list its comment named. The copy took a tool only if it was there. `ANTIC_LLVM_TOOLS` and `ANTIC_LLD_NAMES` are the one list, `antic_llvm_tool_problems` the one check, and `tools/copy-llvm.cmake` the copy, a step of its own that refuses a missing tool. The tests `llvm_tool_list` and `llvm_tools_copy` hold it. |
| M342 | `22884b98` | Eight places spelled the triple and the headers of a target, in two forms of the Linux triple, and one put the headers of clang first. `antic_target_triple` and `antic_target_c_options` of `tools/target-compile.cmake` are the one table. The test `target_triples` refuses a triple spelled elsewhere. |

`21403224` records the three commits in the summary.

The table of M342 normalises the Linux triples to the form clang
writes, `x86_64-unknown-linux-musl`. Every file under `lib/` and
`include/` of the runtime archive came out the same bytes,
`build/s23/runtime-before.sha` against `build/s23/runtime-after.sha`.
`emit_identity` and `link_identity_macos-arm64` are unchanged.

The other half of M342 was a comment of `antic_native_target` that said
the native libraries took the flags of the runtime. They take neither
`-mno-outline-atomics` nor the frame records of the runtime of Linux.
The step keeps the code as it was and makes the comment say why. The
libraries of linux-arm64 that anti-linux built called no `__aarch64_*`
helper. No module of the standard library passes a native library an
Anti function to call back. Adding the options changes the code of
every Linux library, which is a choice of the build for Eddie. The test
`native_hosts` keeps the first reason true.
