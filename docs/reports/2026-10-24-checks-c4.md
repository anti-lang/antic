# The safety check lock-order

The step built C4 of "Compile-time checks of 2026-10-20" in
`docs/decisions.md`. Logs are under `build/drive/logs/checks-c4/`.

## What changed

Commit `41d08acf` builds the check. `src/antic/sema_lock.c` runs once the
checker has checked every function of a module and made the copies of
its generics. It builds the graph of lock orders: an edge from each lock
the code holds to each lock it takes, in a `sync` block, in a public
function of a synchronized class and through a call of a function the
program names. A lock is a `Mutex` field or the hidden lock of a
synchronized class, named by the class that declares it. `sync a, b`
adds no edge between its two locks, and a lock held already adds none.
A call through a table, an interface or a function value is not
followed. An edge that closes a cycle is refused, and the message names
both places:

```text
`Pair.a` is locked here while `Pair.b` is held, and line 39 of `com.example.locks` locks them in the other order [lock-order]
```

A library file carries the locks each function of its module takes and
the edges of its code, in a section that `src/antic/antl_locks.c` writes
and reads. A module that imports it then follows a call into it and
refuses a cycle across modules. A cycle that two libraries close, where
neither imports the other, is refused at `main` of the program. The
format version is 90.

The tests came first and failed, `red.log`. The matrix holds four
refusals, `threads_lock_order_two_mutexes`, `_through_calls`,
`_synchronized_function` and `_cycle_of_three`, and the program
`threads_lock_order_allowed`: `sync a, b` both ways, two objects of one
class, a `Mutex` behind a pointer and one order taken twice.
`tests/errors/lock_order.anti` covers a dev build and `unchecked`. The
cases `modules_lock_order`, `_through_a_call`,
`_of_a_synchronized_class` and `_of_two_libraries` hold the cycles
across modules, over the library trees `lock_orders` and `lock_sides`.
`traps/lock_order_unfollowed.anti` takes a pair both ways through an
interface and through a function value. antic compiles it, and the dev
build reports the conflict.

Commit `694ff0b7` fixes a defect of the new pass before the push. The
table of the locks each function takes was sized before the edges of
the libraries named more locks. Its rows were then read at a wider
stride.
AddressSanitizer stopped antic in the three tests of a cycle across a
library, `asan-4.log` of the first run.

The guide, the overview, the note of warnings, the note of concurrent
classes and the source tree describe the check.

## Places marked until the step sweep

Commit `2bcaca60`. The check refuses `traps/lock_order.anti`,
`traps/lock_orders.anti` and `traps/lock_order_once.anti`, and the
example `orders` of chapter 14 of the guide. Each takes two locks in
both orders on purpose, to show the dev check. The clause
`unchecked(lock-order, "until the step sweep")` stands in the header of
each function that closes a cycle, four functions and `main` of the
guide, so the lines that the reports of the dev builds name stay.

## Mistakes of the task

None found. The task names `sync a, b` with locks of two classes, and
the decision lets it add no edge. The program of the matrix takes
`sync box, bag` and `sync bag, box` and passes.

## Provisional entries added

Four, after the entries of C3 in `docs/decisions.md`:

- Which `Mutex` is a lock of the graph, and the class that names a
  hidden lock.
- A lock held already adds no edge from any lock held.
- What is followed: a call by its name through no table. A call through
  the table of a class takes the hidden lock of a synchronized class
  alone. A worker holds no lock of its starter, and an anonymous
  function is read on its own.
- Where a cycle is refused: once, at the edge of the module that closes
  it, after the edges of the libraries. What a library file carries.
  The refusal at `main` of a cycle of libraries alone, and the edges of
  a copy of a generic of another module.
