# The safety check uninitialized-read

The step built C1 of "Compile-time checks of 2026-10-20" in
`docs/decisions.md`. Logs are under `build/drive/logs/checks-c1/`.

## What changed

Commit `4d2f896f` builds the check. `src/antic/sema_uninit.c` walks the
paths of every function body after E2. A local that `let` or `=` gives
the raw form `alloc(T, n)` is a buffer whose elements are unwritten. A
write at a constant index marks the index on its path, and a read there
needs a write on every path before it. A read at a computed index needs
a write of the whole range first. A loop writes the range when every
turn writes an element at a computed index or lets the buffer leave. A
write at the same local index before the read passes as well. A use of
the buffer other than an element or a test against `none` lets it leave:
a call, a return, a store, a view, an address and a slice. Every element
then counts as written. The guide, the overview and the note of warnings
describe the check.

The tests came first and failed, `red.log`. Four refusals stand in
`tests/matrix/ownership_uninitialized_read_*`: at a constant index, at a
computed index, written on one path of an `if`, and read before the
write in a loop. One program of the allowed reads beside them covers the
`for` loop, the `while` loop, `memset` of the C library, the same index,
a call, a call in every turn, a literal and a returned buffer.
`tests/errors/uninitialized_read` covers a dev build and `unchecked`.

The first run of the suite, `try-host-1.log` to `try-host-3.log`,
refused 31 tests. Each fills an element of `alloc([N]T, 1)` in a loop,
or slices an element never filled. Two readings of the rule followed,
both provisional entries: the path after a loop has what a turn wrote,
and a slice reads no element.

Commit `07c93df4` marks the one place of the repository the check
refuses, with `unchecked(uninitialized-read, "until the step sweep")`.

## Mistakes of the task

- "A read at a computed index needs a write of the whole range first"
  would refuse `p[i] = v; total += p[i];`, which reads the element it
  wrote. The aim of the checks is to refuse only what a check proves. The
  check lets that read pass, by a provisional entry.
- C1 says `alloc` zeroes the elements. "Pointers" in the memory chapter
  of the guide says the memory of a number type is not zeroed, and the
  object model says so too. Only that of a class type is. The check treats both alike.
  The sentence therefore changes nothing here.

## Provisional entries added

Five, after the entries of E2 in `docs/decisions.md`. What a buffer is
and what lets it leave. A loop writes the whole range, and the path
after it has what a turn wrote. A read at the same local index passes. A
write of a part of an element writes it, and a `defer` reads nothing. One
read per buffer is refused on a path.
