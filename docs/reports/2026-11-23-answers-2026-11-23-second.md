## What the answer built

A class names its base in its header as a name and a module, `base_name`
and `base_module` of `struct item`, and not as a type expression, so the
records of item 1 never reached it. `types_item_qualifiers` of
`src/antic/types.c` takes the type the checker gave the item and adds the
record of the base of a class, after the types of the header and before
the type arguments of the base, so the first spelling rule of item 1
holds. `qualifier_add` holds the test of a record that the walk of a type
expression ran before, and both walks call it. `type_signature` of
`src/antic/docpage.c` writes the base through `doc_type_name`, which
reads the records, where `types_name_qualified` wrote the whole path of
its module. `anti.lang.Object` stays left out.

A page now writes `inherits log.Logger` where the header writes
`log.Logger`, `inherits m.Allocator` under `import anti.mem as m`,
`inherits Clock` under a direct import, `inherits lang.Error` where the
header writes `lang.Error`, and `inherits Base` for a base of the module
itself.

The library file carries the record of the base with the records of item
1, in the same form. Its layout does not change, so its format version
stays 100. A library file that the antic before this step wrote holds no
