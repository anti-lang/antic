# Fix step 2, types that contain themselves

Step 2 of "Fix steps" in `docs/audit/summary.md`. Files: `sema.c` and
`types.c`, with `types.h` for the new function. The tests are
`test_sema_cycles` in `tests/unit/test_sema.c`.

## Findings

- S1, fixed in `check_simd_struct`. `simd struct V { _: i64 : 0 }` is
  refused as a bitfield lane. The library reader half of S1 is step 4.
- S5, fixed. The "contains itself" pass tests classes. The four
  reproductions of the audit, `chan A(1)`, `A { }`, `p.zz` and
  `class A { x: int, a: A, }`, are refused with one message.
- S6, fixed. `types_break_cycles` gives the error type to every field
  that closes a reported cycle, so no walk over fields recurses into it.
  `struct S { a: S }` with `v as S` is refused without a crash.
- M2, fixed. A base cycle is refused with "class `B` inherits itself".
  Before the fix `class A inherits B { }` with `class B inherits A { }`
  hung antic.
- M23, fixed. `fixed_layout` checks the product of an array length and
  the sum of the offsets. `v as [16][1152921504606846977]u8` and a
  struct of 2^64 + 16 bytes were accepted as 16 bytes and are refused.
- S11, the counter of `tn`, fixed as a `size_t`. It has no test, since
  it needs 2^31 type names in one run.

## Test first

Before the fix the unit binary reported the class cycles as accepted and
then stopped with SIGSEGV. antic failed on the reproductions under
`build/front-repro/`. S5 and S6 stopped with SIGSEGV and M2 hung. S1 and
both M23 cases exited 0.

The suite found one more crash of the first version. A class whose base
is refused has a base field without a type, which the cycle walk now
reaches. `error_inherits_module` caught it, and `cycle_in` and the new
walk pass over such a field. `test_sema_cycles` holds a case for it.

## Provisional decisions

Four, under "Types that contain themselves" in `docs/decisions-front.md`.
A field that closes a cycle takes the error type. A class that inherits
itself keeps the root. `_` is refused as a lane. No layout past 2^64
bytes is fixed.
