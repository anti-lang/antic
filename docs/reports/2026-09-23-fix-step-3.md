# Fix step 3, constants and walks

Step 3 of "Fix steps" in `docs/audit/summary.md`. File: `sema.c`. The
tests are `test_sema_constants` in `tests/unit/test_sema.c`.

## Findings

- S4, fixed. A chain of constants deeper than 16 links is taken apart by
  a walk with its own stack. Each constant is then evaluated after the
  ones it names. A chain of 3000 compiles under AddressSanitizer, and
  the program exits 184, which is 3000 mod 256. An evaluation nested
  more than 64 constants deep is refused, which a cycle of 3000 reaches.
  The worker walk keeps a queue and a hashed set, so a `worker fn` that
  starts a chain of 60000 calls is checked. Its message on the last
  function is kept. The scan of the functions seen is no longer
  quadratic.
- S7, fixed. A constant that holds a class is refused, and so is a
  field read through a class value. The audit's `Q.x`, which gave 0 in
  place of 3, and `O.inner.x`, which stopped antic, are refused with a
  message. A field default still takes a class literal, since
  `tests/programs/delete_owned.anti` and the owned-module tests use one.
  A field read of a struct constant checks that the value is a struct
  and that the field lies inside it.
- S8, fixed. A repeated array of more than 2^20 elements is refused
  before the product. `[0; 576460752303423488]` stopped antic with
  SIGBUS and is refused.
- S9, fixed. `v is X` on a variant without cases names no example.
  Before, the message read "as `V.`".
- S10, fixed. `doc_check_text` returns for an empty text. No test fails
  before the fix: UBSan does not report `NULL + 0`, which a probe with
  the pinned clang confirmed. The path runs in every doc test.

## Test first

Before the fix the unit binary stopped with SIGSEGV on the chain of
constants, `build/drive/logs/s3-unit1.log`. antic on the reproductions
in `build/s3/` stopped on S4 (both chains), S7 and S8, and printed the
wrong message for S9. The first S7 fix refused every class literal. The
host suite showed 11 failures, since field defaults take class
literals, `build/drive/logs/s3-host-suite.log`. The fix moved the
refusal to the constant itself.

## Provisional decisions

Five, under "Constants and walks" in `docs/decisions-front.md`. A
constant that holds a class is refused. A repeated array in a constant
holds at most 2^20 elements. Deep chains of constants are evaluated
dependencies first, with a nesting bound of 64. The worker walk visits a
callee after its caller's body. `is` on a variant without cases gives
no example.
