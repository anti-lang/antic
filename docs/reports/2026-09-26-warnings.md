# Warnings: where they came from, and one set for our own code

The session built all three trees from scratch with every line captured to a
log, and listed each warning. It put Eddie's three rules on warnings into
`CLAUDE.md`, `docs/c-guidelines.md` and `docs/decisions.md`.

## What the builds from scratch printed

At `c694381`, the host, asan and ubsan trees built from scratch with no compiler
warning. Each printed one linker warning 15 times, once per host link:
`ld: warning: ignoring -lto_library build/deps/clang/lib/libLTO.dylib, file
does not exist`. The build logs of earlier sessions under `build/` hold the
same line and nothing else. The C that the tests compile at run time prints
nowhere, since each script captures the compiler's output and shows it only on
failure. Those compiles had `-Wall -Werror` or no flag at all, so they are
listed below with the gaps.

The Windows sites were found by compiling every file for
`x86_64-pc-windows-msvc` without `_CRT_SECURE_NO_WARNINGS`. The packer now
builds antic and anti for all six hosts under the full set. A run of it on the
Mac wrote the six packages with no warning.

## Gaps closed

- The cross builds of anti_rt, the glue of `anti.regex` and the packer lacked
  `-Wshadow`, `-Wconversion` and `-Wstrict-prototypes`. A Mac builds its
  runtime from the cross build alone.
- Every Windows build defined `_CRT_SECURE_NO_WARNINGS` for all files.
- The C and C++ that the tests compile at run time took `-Wall -Werror` or no
  flag: `run_clib`, `run_anti_bind`, `run_probe`, `run_release_dry_run`,
  `run_linux_libc` and `run_macos_sdk`.
- The warnings now stand in `tools/warnings.cmake` and, for the five
  libraries, `src/native/warnings.cmake`. The test `warning_set` refuses a
  warning flag spelled anywhere else, and it refuses the tree at `c694381` at
  48 places.
- `tests/run_start.cmake` compiles C with no warnings, and no test runs it.

## Third-party flags

PCRE2 and SQLite take no warning flag, Mbed TLS the `WARNING_CFLAGS` of its
`library/Makefile`, miniaudio the flags of its `CMakeLists.txt` and raylib
those of its `src/Makefile`. Only raylib warns.

## Questions for Eddie

1. The `-lto_library` warning. The pinned clang always passes it to Apple's
   linker, and the archive of `anti-lang/llvm-tools` ships no
   `libLTO.dylib`. Three options: ship `libLTO.dylib` in that archive, link
   the host programs with `ld64.lld` as the packer already does for macOS, or
   leave it. Each is a build configuration, which is your decision.
2. Four `[provisional]` entries stand under "Warnings" in
   `docs/decisions.md`. They are the two files of flags and the Makefile's
   flags where a project has two builds. The other two are `-isystem` for
   third-party headers in our compiles and the platform layer of the tools on
   Windows.
3. `tests/bind/layout.h` is ours and stands in for a foreign header. Reading
   it as a system header keeps its wide enum. The other way is a pragma at
   that line.
