# `f16` as a storage type

The task: `f16` from "Small items, round three" of
`docs/anti-language-additions.md`. It is sixteen bits in a field, an array or
a slice, a read gives an `f32` and a write takes `as f16`, with no arithmetic.
The conversion is one instruction on ARM64 and x86-64-v3 and a runtime routine
at `v1`, with tests on both architectures through the assembly.

## What changed

- `f16` is a keyword and `TYPE_F16` a type with the layout of `u16`. The
  checker writes every read of an `f16` as an `as f32` marked `promoted`.
  The target of an assignment, the operand of `&` and the place of an atomic
  call are checked with `check_storage`, which keeps the `f16`. `as f16`
  takes an `f32`, and a float literal before it is an `f32`. Any operator on
  an `f16` is refused with `` `f16` has no arithmetic, convert with `as f32` ``,
  and so is a compound assignment. A parameter or a result of type `f16` is
  refused.
- The IR holds an `f16` as its bits in an `i16`. `hext` and `htrunc` convert
  them to and from `f32`, and the optimizer folds both.
- `rt/f16.h` holds the one conversion, round to nearest with ties to even and
  NaN payloads kept. `rt/f16.c` exports `anti_rt_f16_to_f32` and
  `anti_rt_f32_to_f16`, and antic folds constants with the same functions.
- `select_module` takes the CPU level. x86-64-v3 writes `vmovd` with
  `vcvtph2ps` or `vcvtps2ph $4`, and `v1` and `v2` call the runtime. ARM64
  writes `fmov` and `fcvt` between `hn` and `sn` at every level. The level
  table gains `CPU_F16C` at v3.
- The header writes `uint16_t`. Reflection has the type id `F16` after
  `Class`, `get` and `set` carry a `Float`, and `serialize` and `deserialize`
  cover the field. The library format is version 36.
- `docs/decisions.md` has the new section "`f16`", `docs/notes/floats.md`
  the choices inside the compiler, and the syntax overview marks `f16`
  built. The spec's list of added built-in types names `f16`.

## Tests

- `program_half` and `program_half_macos-x86_64` run
  `tests/programs/half.anti`, the second at `--cpu v1` under Rosetta, so the
  instruction and the runtime routine print the same bits. The program covers
  ties, overflow to infinity, subnormals, `-0`, a NaN payload, a field, a
  class default, an array, a slice, a pointer, a constant and an atomic
  field.
- `f16_<target>_<level>` checks the assembly of `tests/dump/half.anti`: F16C
  at v3, the calls at v1 and v2 on Linux and Windows, `fcvt` at `armv8.0` and
  `armv8.5`. `asm_half_<target>` assembles it for all six targets, and
  `asm_half_v1_<target>` the three x86_64 targets at v1.
- `test_f16.c` checks both routines against values computed with `ldexp`:
  every half, and every midpoint between two halves with its neighbours.
- `listing_error_half` holds the thirteen refusals. Unit tests cover the IR
  of a read and a write, the header, the type ids and a constant and a struct
  read back from a library file. `std_reflect` and `std_serialize` gained an
  `f16` field.
- Pins rewritten on the Mac: `tests/emit-identity/programs.sha256` gained the
  six digests of `half` and no other line changed. The digest of
  `tests/link-identity/return42.macos-arm64.sha256` changed because the build
  id hashes the runtime library, which gained `f16.o`.
  `tests/modules/scale.antl.hex` changed in the version byte, the kind of a
  function type and the op numbers after `ftrunc`.

## What failed

- Structs take no field defaults, so the class default moved to a class in
  the program test. `size_of(Pixel)` then became 6, and the expectation
  followed.
- An atomic `f16` field failed at `load()`, since the promoted read hid the
  atomic place. The place is now checked as storage, and `add`, `sub`, `and`
  and `or` are refused.
- An export constant of `f16` is refused by the existing rule, so the header
  test dropped it.
- The docs-style checker found long sentences in new comments and older
  ones in touched files, all rewritten.

## Provisional entries

Under "`f16`" in `docs/decisions.md`: the read as an implicit `as f32`,
`as f16` from `f32` alone, no `f16` parameter or result, variables and
constants of `f16`, atomic `f16` fields, the IR form, `uint16_t` in the
header, and reflection.

## Questions

- "CPU levels" in the additions says `armv8.2` adds half-precision
  conversion. `fcvt` between `h` and `s` is in ARMv8.0, and the `f16` item
  asks for one instruction on ARM64, so every ARM64 level converts in one.
  Should that line read half-precision arithmetic?
- Separate from this step: an `atomic` `f32` field passes the checker, and
  `add` on it stops in selection with `` `trunc` on arm64 ``.
