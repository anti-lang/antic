# Fix step 11, runtime regex glue and traces

Step 11 of "Fix steps" in `docs/audit/summary.md`. Files `src/rt/patterns.c`,
`src/rt/trace.c` and `src/rt/trace.h`, with `src/std/anti/regex.anti` for the
stop of a missing group. Logs are in `build/drive/logs/s11-*`.

## Findings

| ID | Result |
|---|---|
| S25 | Fixed. `fits_span` compares `at <= span - length` after `length <= span`, with no sum. It serves `anti_rt_regex_patch` and `anti_rt_bytes_patch`. |
| S26 | Fixed. `has_group` bounds a group number by `anti_rt_regex_group_count` of the pattern, in `anti_rt_regex_group`, in `expand` and in `patch`. The stop of a missing group takes the match and names the count of the pattern, not the field. |
| S27 | Fixed. `symbolize` takes the image from the address on all three systems: `image_at` on macOS, `module_at` on Linux and on Windows. `anti_rt_trace_frame` uses the same helper. |

## Tests first

Each test failed before its fix:

- S25, `programs/pattern_patch.anti`: an offset of `INT64_MAX` read by
  `text.parse_int`, for a byte sequence, a pattern literal and a compiled
  pattern. Before the fix the sum wrapped and a byte before the data changed
  (`s11-t2.log`). An offset one below the top is also tested.
- S26, `traps/pattern_group_count.anti`: `m.count = 50` and then
  `m.group(50)` read past the ovector and gave an empty group instead of
  stopping (`s11-t1.log`). It now stops with "the pattern has 3 groups".
- S27, `trace/forged.anti`: a trace written to text, every `base` set to 16
  and every `module` to a path that does not exist, read back with
  `Object.deserialize`. It crashed with a segmentation fault on macOS
  (`s11-t4.log`). It now names `forged.inner`, `forged.outer` and
  `forged.main`, the same as the captured trace.

The open templates in `programs/pattern_replace.anti` (`<$`, `<${`, `<${1`,
`<${k`, as literals and in variables, `${2` against a compiled pattern and
`$99999999999999999999`) passed before any change: `anti_rt_regex_piece`
checks each index against the length already. They stay as tests of the
reader.

The Linux and Windows branches of `trace.c` compiled for every target with
warnings as errors. `trace_forged` did not run on a VM in this step.
