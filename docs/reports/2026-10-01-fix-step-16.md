`sema_export.c`, `sema_pattern.c`, `sema_stmt.c`, `sema_expr.c`,
`sema_call.c`, `sema_generic.c` and `sema_copies.c`. The fix also needed
`sema.c`, `sema_doc.c`, `sema_checker.h`, `ast.h`, the new `ast_walk.c`,

## Tests first

- `program_checked_once`, new. It holds `-(-a)`, `-taken(k)`,
  `taken(j).to_slice()`, `taken(i)[2]` and `pick(h, &sp).reach()`. A chain
  of forty calls through function fields follows. Before the fix antic
  crashed on it with a segmentation fault (`s16-red-checked-once.log`). Each form alone gave `unknown name
  Vec2.neg`, `k was moved into taken` or exit 139
  (`build/s16/*.log`). The chain of forty did not finish in 30 s
  (`s16-red-chain40.log`). It passes after (`s16-t2.log`,
  `s16-green-chain40.log`).
- `listing_error_worker_walk`, new. A `delete` in a function a struct
  literal and a tuple call, in a `let ... else` body and in the handler of a
  guarded `let` of a `worker fn`. Before the fix antic compiled it
  (`s16-red-walk.log`).
- `listing_error_assert_call`, new. A call inside a tuple in an `assert`
  condition, which the old walk missed (`s16-red-walk.log`).
- `silent_doc_declared`, new. A doc comment that names every declared type.
  Before the fix `ByteRegex`, `Match` and `ByteMatch` drew
  `doc-unresolved` (`s16-red-docdeclared.log`).
- The field lookup, `copy_in_chain` and `copy_name` had no observable
  defect left. No program names the unit break `_`, and a copy never meets
  its generic after substitution. A long name of a function copy was
  refused with the same message before. Those three are the removal of
  copies, covered by the existing suite.
