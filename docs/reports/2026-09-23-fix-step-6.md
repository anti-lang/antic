# Fix step 6: antic layout

Step 6 of the fix steps of `docs/audit/summary.md`, in `src/antic/layout.c`.

## Findings

- S14, fixed. `fold_op` refuses a symbolic `sdiv` or `srem` whose left operand is the least value of its type and whose right operand is -1. The test is at the width of the operation, as `reports_undefined` tests it for constants. The unit test `least_by_minus_one` takes both operations at `i64` and `i32`. Before the fix it failed with the array length the wrapped quotient gave.
- S20, fixed. `bit_unit` refuses a bitfield whose unit is larger than its aggregate, before it moves the unit back. The unit test `unit_past_aggregate` takes a packed struct of 3 bytes and a packed union of 5. The listing `listing_error_layout_unit` takes `packed struct P { a: u32 : 20 }` from source.
- S21, fixed. Every sum and product of a size in `compute` goes through `add_size`, `mul_size` and `round_up`, which note an overflow. An aggregate whose size in bits needs more than 64 bits is refused with its name and the target. That covers the array product of line 218, the offset and size of line 251, and the other roundings of the loop. The unit test `size_overflows` takes an array of 2^61 + 1 `u64` and a struct whose field after an array of 2^61 - 1 bytes wraps. Before the fix the second one hung in `flatten`, since the struct got the size 0. The listing `listing_error_layout_size` takes the array from source.

## Decisions

Three `[provisional]` entries in `docs/decisions-library.md`:

- A bitfield unit larger than its aggregate is an error of the back end. Reading it with two accesses would change `lower.c`, which lies outside this step.
- The size of an aggregate in bits fits 64 bits.
- A symbolic `sdiv` or `srem` of the least value by -1 is an error of the fold.
