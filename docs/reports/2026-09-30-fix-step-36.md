# Fix step 36: tests that pass whatever the code does

Step 36 of "Fix steps" in `docs/audit/summary.md`: M54, M55, M56 and the
minor finding on tests that drop out, from `docs/audit/tests.md`. The logs
lie in `build/drive/logs/s36-*.log`.

M56. `link_linux` and `link_linux_syntax` join the listing errors, and
both pass. The new test `errors_registered` fails for a program of
`tests/errors/` that no registration or runner names, and for an `.err`
file without its program. Without the two new lines it names both files
(`s36-reg-red.log`).

M55. `Key` of `owning_values`, `walk_owned_parts` and `alloc_owning`
counts itself alive, its `destruct` lowers the count, and every check
prints both counts. A scratch program that destroys one `Key` twice
prints `leaves 0 keys -1`, so the new count catches what the leaf count
missed. `Shelf` and `Bin` of `own_params` print a line in their
`destruct`. Every count reads 0 and every teardown line stands once, so
no double teardown was hiding. The digests of `emit_identity` change for
the four programs alone.

M54. `tests/run_expect.cmake` is the one runner of every refusal and
warning test, and `run_error.cmake` is gone. It compares the exit status
as a number and then the output, byte for byte against a file or with a
pattern. A crash gives a text and fails. The helper `add_expect_test`
registers the 24 tests that used `PASS_REGULAR_EXPRESSION` and the 131
that used `run_error.cmake`. Six refusals of a source in `tests/errors/`
compare new `.err` files, among them the patterns that spanned lines or
held a `;`. `expect_runner` runs the runner on commands of
CMake and fails on a CMake file of the repository that sets
`PASS_REGULAR_EXPRESSION`. It fails before the runner exists
(`s36-self-red.log`) and finds the 24 places in the previous
`tests/CMakeLists.txt`. A scratch ctest project shows the defect: a
`cmake -E echo` of the refusal passes a test with the old pattern
(`s36-pass-pattern.log`).

Minor. `no_paths`, `asserts` and `checks` read a binary with
`file(STRINGS)` and register on every host. `file(STRINGS)` found the
debug map of the development `antic`, 82 N_OSO names of objects under
`build/host`, which the `strings` of macOS never read. `no_paths` leaves
those names out, listed by the `llvm-readobj` of the runtime archive, and
fails on a path planted anywhere else. The three runners of
`--memory-checks` print `SKIP:` on a windows-arm64 host instead of a
pass. The raymath comment above `no_paths` moves to the raymath test.

## Provisional entries

- Under "Errors, warnings and checks": antic exits with 1 on a refused
  program, 2 on a refused command line and 70 when out of memory. Every
  refusal and warning test checks the status.
- Under "Libraries and runtime": `no_paths` reads every byte and leaves
  out the debug map of a Mach-O file.

## Questions for Eddie

- Should the development build of antic map its debug map with
  `-Wl,-oso_prefix`, so `no_paths` needs no exception? It is a choice of
  the build configuration, and it would change how lldb finds the
  objects.
- `antic -S -I tests/errors anti/rt.anti`, a relative source under a
  root, exits 0 with no message, and the absolute path is refused. With
  `-I .` and `anti/text.anti` the module path becomes `text`. The entry
  on module paths in `docs/decisions.md` says the path is taken under the
  first root that holds the source. The step does not cover the driver,
  so this is not changed.
