## Findings

- M24. Fixed. `arith_float_literal` of `src/antic/arith.c` converts a
  float literal from its bytes and its length through a `struct text`.
  The range check of the checker, the constant folder and `float_literal`
  of lowering call it, and the three copies into `char digits[128]` are
  gone. `arith.c` lies outside the listed files. It holds the constant
  arithmetic that the checker and the back end share, so the one helper
  sits there.
- M25. Fixed. The nine name buffers of `lower.c` that the finding lists
  are `struct text`: the teardown and the copy, both uses of `init_name`,
  the interface descriptor and table labels, the thunk, the reach
  function and the `construct` helper. `c_name` of `header.c` appends to
  a `struct text`, and each caller frees it.
- M32. Fixed. A float constant whose text holds neither `.` nor `e` gets
  `.0`, so `2.0` is `2.0f` as an `f32` and `2.0` as an `f64`.
- M33. Fixed. `class_view` allocates one entry per member of every level
  of the chain, which bounds what `chain_functions` finds.
- M34. Fixed. `quoted` of `debug.c` escapes `\` and `"` in `.file`,
  `.cv_file` and the name of the DWARF compile unit, and writes a control
  byte as an octal escape. llvm-mc accepts `"src\\Users\\ma\"in.anti"`.
  On the command line the module path check refuses such a name before
  lowering, so the path reaches the directives from a library file.
