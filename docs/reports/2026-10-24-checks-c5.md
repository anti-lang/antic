# The warning blocking-under-lock

The step built C5 of "Compile-time checks of 2026-10-20" in
`docs/decisions.md`. Logs are under `build/drive/logs/checks-c5/`.

## What changed

Commit `9706ca48` builds the warning. The pass of the lock orders in
`src/antic/sema_lock.c` records every wait of a function, a `recv`, a
`send`, a `select`, a `join` and a `join_all`, and each call of a
function the program names, in the order of the text. A function waits
when it holds a wait or calls one that waits. A wait, or a call of a
function that waits, gets the warning inside a `sync` block or in a
function of a synchronized class that holds the hidden lock. The message
names the innermost lock and, for a call, the first wait the callee
reaches:

```text
`next_two` may wait in `recv` on line 7 of `com.example.waits` while the `sync` of line 19 holds its lock [blocking-under-lock]
```

A library file carries the first wait of each function of its module
that waits, so a call into a library warns as well. The format version
is 91. The pinned library files and the unit test of the format hold the
new count, and a wait kind past the last is damage.

The tests came first. Before the pass, antic compiled each of the twenty
refusals without a word. The matrix holds each kind of
wait directly and through a call, in a `sync` block and in a function of
a synchronized class, as `threads_blocking_*`. The program
`threads_blocking_outside_a_lock` holds the same waits outside a lock, a
`construct` of a synchronized class, an anonymous function written in a
`sync` block and a worker started there, and compiles without a word.
`errors/blocking_under_lock.anti` holds a dev build, the innermost lock,
`sync a, b` and `allow` before a statement and in a header.
`allow_levels.anti` holds `allow` in a release build, and
`modules_blocking_under_lock` a wait inside the library tree `waits`.

## Where it fired

The front end ran over every `.anti` file of the repository, `scan.log`.
The warning fired in the context `in_sync` of three matrix programs,
`threads_channel`, `threads_dispatch` and `threads_select`, whose release
builds it stopped, `host-2.log`. None of those waits can block for long.
The channels are local to the block and hold their values or are closed,
and the workers take no lock. Commit `c9a3eadc` silences each with an
`allow` before the `sync` block that says so. Nothing in `src/std/`, the
guide or the overview waits under a lock.

## Mistakes of the task

None that contradicts a document. The task names a `send` on a channel
that can be full and a `select` without `else`. Every channel has room
for one value or more and can be full, and a `select` has no `else`, by
the parser and "Locking and channels". The warning therefore counts
every `send` and every `select`, and a provisional entry says so.

## Provisional entries added

Three, after the entries of C4 in `docs/decisions.md`:

- Every `send` and every `select` counts as a wait.
- Where the code holds a lock, and which calls are followed: those of C4,
  with a worker and an anonymous function holding none.
- What the message names, what a library file carries, and that a copy
  of a generic of another module warns of nothing in its body.
