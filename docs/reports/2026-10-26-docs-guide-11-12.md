## Older documents against the code

- `11-ownership.md` said that the address of a local stored in an `own` field compiles. `escaping-local` refuses it where a parameter or `self` reaches the object, and a local stored there moves. It compiles for memory the function allocated alone, as `build/guide1112/p/own4.anti` shows.
- `11-ownership.md` said that a reference stored where the check cannot follow keeps the run-time checks of dev mode and `--memory-checks`. `memcheck.c` puts no check on an address in the frame, and a stale stack pointer has no poisoned bytes. `build/guide1112/p/esc.anti` reads one under the option and prints garbage with no report. The `[provisional]` entry of E1 under "Compile-time checks of 2026-10-20" in `docs/decisions.md` says the same as the old text. The code wins, and the guide says what the code does.
- `11-ownership.md` named "the versions of a `Pool`" for the check of a handle. A `Handle<T>` holds a generation, and the version of `Pool<T>` counts the changes of an element.
- `12-memory.md` said at the pointer section and in a pitfall of slices that the return of a pointer to a local compiles. `escaping-local` refuses both.

## Findings

The program stops with a segmentation fault in dev, in release and under `--memory-checks`. `tests/matrix/errors_delete_of_the_error_a_handler_binds.anti` holds the three exits, and its three tests stand in `tests/known-failures.txt`. The guide shows no such handler.

## Questions answered from the code

- Does C2 remove a dev check for an index it proves inside the range? No. `lower_bounds_check` writes every check, and C2 only refuses.
- Does `yield` move an `own` parameter? Yes, as `or_spare` of `places` shows, and the function tears the parameter down when no handler ran.
- Does a move into an `own` field clear the local? No. The local is a pointer, and no teardown waits for it.
- Does a plain pointer parameter stored into an `own` field compile? Yes, as `own1.anti` shows.
- Does a closure made before a `delete` and called after it compile? Yes, by the `[provisional]` entry that E2 reads a closure where it stands.
- Which line does a `//! error:` mark count? The line of the file the runner writes, which drops the blank lines between items.
