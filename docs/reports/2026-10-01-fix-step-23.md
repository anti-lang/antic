# Fix step 23, antic C header

Step 23 of "Fix steps" in `docs/audit/summary.md`: M07, M19, M51, M52
and the minor `neon` name. The fix changed `src/antic/header.c` and
`src/antic/lower_desc.c`. The order of a table moved to `sema_table_of`
of `src/antic/sema_class.c`, which both read. Logs are in
`build/drive/logs/s23-*`.

Status: green and pushed.

## Findings

| ID | Result |
|---|---|
| M19 | Fixed. `sema_table_of` is the one owner of the table order, keyed by name and parameter count. `table_of` of lowering and `class_view` of the header call it, and `chain_functions` is gone. `sema_root_hook` replaces `lower_hook_name`, which read the root's names from the same table. A slot whose name an earlier slot has takes `_`, so two statics of one name are `make` and `make_`. A static gets no wrapper. |
| M07 | Fixed. A tuple or a function inside a name ends with `_end`, and a function writes its parameters and result. A struct, class, variant or enum writes its C name through `c_type_name`, so the copy `export type IntBox = Box<c_int>` is `anti_tuple_IntBox_i32` and no longer `anti_tuple_Box<i32>_i32`. `variant_view` uses the same helper. A wrapper whose slot is the name of a helper takes one `_` more, and a function named `vtable` gets no prototype beside the table type `<Class>_vtable`. The generic variant of the finding cannot reach the header today: `sema_generic.c:2201` refuses `export type` of a variant. It goes through the helper all the same. |
| M51 | Fixed. `class_uses` emits what the fields of a class hold by value, and the parameters and results of its table and its `construct`, before the class. `nested_views` does the same for each nested type. `emit_uses` takes classes and every tuple a type names. |
| M52 | Fixed. An infinite constant is `INFINITY` with its sign and a NaN `NAN`, of `<math.h>`, which the header includes when one stands in it. `integer_literal` writes the least `int64_t` as `(-9223372036854775807 - 1)` and an unsigned value past `INT64_MAX` with `u`, for a constant and for an enum value. |
| `neon` | Fixed. The dead first value is gone, and a `bool` lane takes `uint8x16_t`. |

## Tests first

`clib_names` gained each case, compiled under the warnings of the
repository and run from C. Before the fix the C program did not compile
(`s23-red.log`, `s23-red2.log`). The errors were `self` undeclared in the
wrapper of a static and `anti_Named_init` and `anti_Named_construct`
declared twice. `anti_tuple_tuple_i32_i32_i32_i32` and
`anti_tuple_fn_i32` were each defined twice. The fields of `Holder` had
incomplete types, a tuple of a class function was declared in a parameter
list, and `inf.0` stood in the header. The unit test `simd_bool_lanes`
of `test_header.c` failed on `uint64x2_t`. Both pass after the fix
(`s23-green3.log`).

## Left

A pointer field to an exported class or struct declared later still
fails: `export class First { pub next: ?*Second }` before `Second` gives
`unknown type name 'Second'`. M51 names the types a class holds by
value, and a pointer needs a typedef of every exported type ahead of the
aggregates. That changes the form of every header, so it waits for
Eddie. Question: should the header declare `typedef struct X X;` for
every exported struct, union, class and variant before the first
aggregate?
