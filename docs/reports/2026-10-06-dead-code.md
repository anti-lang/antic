# Dead code

Eddie decided on 2026-10-06 that an executable carries no code it never uses. Every link
antic runs now drops the sections that nothing reaches, on all six targets. The work is
commit `9b03c9e9`.

## What changed

- `src/antic/linker.c`: `drop_unused` adds `-dead_strip` on Mach-O, `--gc-sections` on
  ELF and `/OPT:REF /OPT:NOICF` on COFF. Every program link and every shared library
  link calls it, for lld and for `--linker platform` alike.
- `src/antic/llvm_run.c`: llc runs with `-function-sections -data-sections` for ELF and
  COFF, in release and dev mode. Under `--lto` lld splits the sections itself.
- `CMakeLists.txt`: `antic_runtime_sections` holds `-ffunction-sections -fdata-sections`
  once, for every target that is not macOS. The runtime objects, the licence stub and
  the glue of `anti.regex` in `src/native/pcre2.cmake` take it. The bitcode runtime
  and the third-party sources keep their flags.
- `src/antic/llvm_emit.c`: `roots` writes one `llvm.used` per module. It names the
  notice `anti_licenses` when the driver will append it, and every function with the
  new IR mark `by_name`. `llvm_emit_licenses` no longer writes a `llvm.used` of its
  own, because a module holds one.
- `docs/decisions.md` carries the decision under "Scope and toolchain", with a
  `[provisional]` entry for `/OPT:NOICF`. `docs/notes/llvm.md` names the llc options.

## Roots kept, and why

| Root | Why it is reached without a reference | How it stays |
|---|---|---|
| `anti_licenses` | Every binary ships the licence texts, and `src/rt/trace.c` and `anti symbols` read the build id in it by symbol name or by export | `llvm.used`: `SHF_GNU_RETAIN`, `NoDeadStrip`, `/INCLUDE:anti_licenses`, each read back from the objects |
| `__asan_default_options` | The ASan runtime of macOS looks it up by name. The first full run dropped it, and `memory_checks`, `memory_checks_list` and `anti_memory_checks` aborted instead of exiting with status 1 | `by_name` in `memcheck.c`, then `llvm.used` |
| `@anti.package` | A C linker of the user may drop it from a static library | its `llvm.used`, unchanged |
| `llvm.global_ctors`, runtime constructors | The loader runs them | `.init_array`, `__mod_init_func` and `.CRT$XCU` are roots of every linker |
| Names a plugin binds against | A plugin resolves them in its host at load | `-export_dynamic`, `--export-dynamic` and the `.def` exports are roots |
| `anti_rt_provides`, `anti_rt_imports` | The loader reads them from a plugin by name | exports of the plugin, by `-shared`, `-dylib` or its `.def` |
| `anti_rt_slots`, `anti_rt_injectable` | Read by the runtime | a direct reference from the code that reads them |

mixed_work for linux-arm64 grows on disk and shrinks in memory. `.text` loses 38 KB and
`.eh_frame` 6 KB, while the symbol table, which is never loaded, gains 2,548 AArch64
mapping symbols, one `$x` or `$d` per new section, about 61 KB.

Every program printed its old line, compared before against after: macos-arm64 and
macos-x86_64 at `v1` under Rosetta on the Mac, linux-arm64 and linux-x86_64 on
anti-linux and windows-arm64 on anti-windows. mixed_work at `v1` is refused, since
`anti.regex` stands at `v3`. The windows-x86_64 programs end with `0xC0000005` under
the emulation of anti-windows, before and after alike, at `v3` and at `v1`.

## Tests

`dead_code_<target>` failed on all six targets before the change, each for holding
`anti_rt_exit`, and passes on all six after. ELF and Mach-O are read with
`llvm-objdump --syms`. A Windows image has no symbol table, so the test reads the names
of its PDB, as `pdb_names` does. The program sits in `tests/link-identity/hello.anti`,
because a file in `tests/programs/` would join the manifest of `emit_identity`.

The builds of all three trees on the Mac print no warning. The skips are the tests
that need a Mac, a release key or a sanitizer runtime the host lacks.

The four failures predate the change. Eddie asked for them to be fixed before the push.

- `program_mixed_work_lto_full` on anti-linux printed the warning of lld that the
  program's triple `aarch64-unknown-linux-gnu` differs from the runtime's
  `aarch64-unknown-linux-musl`, the same at `39bfd330`. The runtime as bitcode of musl
  now compiles for the program's triple, `[provisional]` in `docs/decisions.md`.
  `cross_link_<target>` refuses any output of a link, and the four Linux LTO links of
  the Mac failed that check first (`45e8bcee`).
- `program_mixed_work_lto_thin` on anti-linux: ld.lld ended by signal 11, the same at
  `39bfd330`. gdb showed a worker thread 504 frames deep. The pinned ld.lld of
  linux-arm64 is a static musl program whose `PT_GNU_STACK` asks for no size, so musl
  gives each thread its small default stack. A copy with the request patched to 8 MiB
  linked the program, which printed its line. With the triples in agreement the test
  passes with the pinned ld.lld. The default stack then sits near what ThinLTO needs
  for this program, and a larger program may cross it again.
- `direct_calls` on anti-windows looked for `@table_hook.main`, and COFF names the
  function `_A10table_hook_main`. It now reads every spelling, as
  `run_trap_table.cmake` does, and runs as `direct_calls_<target>` for six targets on
  every host, which failed on the Mac for both COFF targets first (`16b8b284`).
- `profile_guided` on anti-windows read `used.bc`, and `--keep-llvm` writes
  `used.exe.bc` there. It now reads the name of the output (`3da62a05`). The VM run
  at `45e8bcee` then failed one step later on `@mixed_work.main`, the COFF spelling
  again, and the test now reads every spelling (`59c8fb3e`).
