# Solid: step 3, texts and memory that runs out

The step fixed the five findings of step 3 of "Fix steps" in
`docs/audit/summary.md`: S311, S312, M301, M302 and M330. It follows
decision 4 of "Decisions of 2026-10-11", in one session on 2026-10-16. Each starts with
the test that shows it, and each failed before its fix. The logs lie in
`build/drive/logs/`, under names that start with `step3-`.

## Findings closed

| Finding | Commit | Cause |
|---|---|---|
| S311 | `95b0a747`, `6d37e23c` | Lowering sized a snapshot on the heap as its record and the bytes of each captured `str`, and `anti_rt_snapshot_text` wrote no NUL after them, so the `ptr` of a captured text was no C string. |
| S312 | `07caeed4` | `anti_rt_builder_take` gave the literal `""` when the byte of an empty text found no memory, and `take_in` gave it when its allocator had none, while both tell the caller to free the text. |
| M301 | `43a52d7c` | `anti_rt_dup` and `anti_rt_copy_buffer` gave NULL when `malloc` failed, and the code antic writes handed it on as a `*T` or an owned buffer. |
| M302 | `b06fe3ad` | `from_errno` and `from_win32` kept the text of the system without a copy, in storage that the next call of the thread writes over. |
| M330 | `ba344114`, with the builder in `07caeed4` | The library answered memory that runs out five ways: a stop, a failure, dropped bytes, a dropped option or argument, and a literal. |

`0e467a2d` writes the commit of each into its row of the summary.

- S311. `matrix_closures_snapshot_on_the_heap_keeps_the_nul_of_a_text`
  captures two texts in an `own fn` and reads each with `strlen`. Before
  the fix the first read on into the second in all three modes. The
  effects dump, the manifest of `emit_identity` and the excerpt of
  chapter 5 of the guide take the byte more.
- S312. `rt_oom_tests` links the builder with `malloc` and `realloc`
  replaced by stand-ins that refuse on request, and
  `tests/run_rt_oom.cmake` checks that `take` of an empty builder, an
  append, a pad and a count no size holds each stop with the message of
  `anti_rt_out_of_memory`. The counts no size holds move there from
  `unit_rt_bounds`, whose old lines expected the builder to keep what it
  held. `trap_take_in_refused` takes `take_in` over an allocator with no
  memory. `SinkLogger.new` of `log.anti` needed no change, since `take`
  gives no literal any more.
- M301. `rt_oom_tests` takes `dup` of an object and the copy of a buffer
  with `malloc` refused. `anti_rt_copy_buffer` may now end the program, so
  its row of the memory effects drops `willreturn`.
- M302. `program_abi_system_error` sets four `errno` codes and two Win32
  codes through `tests/abi/system_error.c`, and compares each message with
  a copy taken when its error was made. Before the fix the message of the
  unknown code 9001 changed on the Mac.
- M330. `std_out_of_memory` reads `src/std/` and refuses an `alloc(T, n)`
  without the stop and a failure of "out of memory". Before the fix it
  named `args.anti`, `fs.anti` and `lang.anti`. `trap_error_text_refused`
  and `trap_trace_names_refused` take `Error.text` and
  `StackTrace.symbolize` over sizes no host gives. `json.unquote` loses
  its failure of code 1, since the builder now stops. The header of
  `anti.mem` states the rule once.

## Provisional entries

One entry of `docs/decisions.md`, under "Standard library phase":

- M302. The message of a `SystemError` is a copy that the runtime keeps
  to the end of the program. It keeps one copy per distinct text, through
  `anti_rt_text_kept`.

The feature freeze holds. `anti_rt_text_kept` is a function of the runtime
that `anti.error` declares, and no public item of the library. The defect
M302 cannot be fixed without it, since an error cannot own the bytes of
its message: `dup` copies the `str` as a pointer, and a `copied` hook
that would repair the copy is dropped under `--no-hooks`.
