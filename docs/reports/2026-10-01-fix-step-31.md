# Fix step 31, runtime text and `Object.deserialize`

Step 31 of "Fix steps" in `docs/audit/summary.md`: M32, M38 and M22, the
variant, `?T` and cut text tests of M43, and the refusal of
`[injections]` in `rt.configure`. Logs are in `build/drive/logs/s31-*`.

Status: green and pushed.

## Findings

| ID | Result |
|---|---|
| M22 | Fixed. Every number of the deserialize reader is checked against the JSON grammar, and an integer field reads through `anti_rt_json_integer` and the new `anti_rt_json_unsigned` of `json.c`. `strtoll` and `strtoull` are gone from `registry.c`, so `json.c` is the one owner of the conversion. |
| M38 | Fixed. `read_text` refuses a NUL byte and bytes that are no UTF-8 at the member, through `anti_rt_text_invalid`, which `std.h` now declares. |
| M32 | Fixed. `anti_rt_last_error_text` moved to `platform_windows.c` and calls `FormatMessageW`, then converts the UTF-16 to UTF-8. The errno message and the Win32 code moved into the platform files with it, so `errno.c` holds no host branch. |
| M43, part | Fixed for the variant, `?T` and cut text cases of `Object.deserialize`. The other readers of M43 belong to other steps. |
| `rt.configure` | Built. A file that `rt.configure` names, and every file it includes, refuses a key of `[injections]` with its position and names `--anti.conf` and `ANTI_CONF`. |

## Tests first

- M22, M38 and M43: `tests/std/deserialize_input.anti`. Before the fix
  it accepted `+5`, `007`, `+0`, `+1.5`, `.5`, `01.5` and `1.`, a
  `\u0000` and three texts that are no UTF-8, and `"at":5` and
  `"at":[1,2]` for a `?Point` (`s31-red.log` and the program's output).
  Every cut of a whole text was already refused.
- The `?T` cases found one more defect. A struct field with a
  descriptor took any value and kept its default, so a `?Point` held a
  value the text never gave. Such a field now takes an object alone.
- M32: `rt_wide_text` refuses an ANSI entry point of Windows in
  `src/rt/`. It failed on `FormatMessageA` and on `GetModuleHandleExA`
  of `loaded.c`, which now calls the W form (`s31-wide.log`). The wrong
  bytes themselves show only on a Windows whose language has messages
  outside ASCII, and no test machine runs one. The six Windows runtimes
  compile with the change under the warning set. No VM ran this step.
- `rt.configure`: `conf_configure_injections` and
  `conf_configure_injections_include` failed with the old message,
  `anti.log.Logger is no injectable interface of this program`, which
  took the table as an interface name. The next red run of
  `deserialize_input` wrote over that log, so `s31-red.log` holds the
  red output of `deserialize_input` alone.
- `test_json` gains the cases of `anti_rt_json_unsigned`.

The first host run failed `link_identity_macos-arm64`, because the
runtime that `return42` links changed (`s31-host-ctest.log`). The digest
in `tests/link-identity/` is the one this Mac gives, as the test asks.
