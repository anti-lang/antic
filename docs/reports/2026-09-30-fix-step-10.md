# Fix step 10: the whole-program pass and hooks

Step 10 of "Fix steps" in `docs/audit/summary.md` closes S19 and S29.
Each fix began with a test that failed. The logs are under
`build/drive/logs/`.

## Findings

| ID | Result | Test that failed first |
|---|---|---|
| S19 | fixed | `plugin_host` printed `from the host` and `asked 0` for the library's object |
| S29 | fixed | `plugin_host` built a plugin with `--no-hooks` without an error |

- S19. `devirtualise` of `src/antic/whole.c` no longer runs for a plugin,
  nor for a program that injects an interface or calls `plugin.load` and
  is not built with `--closed`. The host of `tests/plugin/` and the
  program with an injected provider each hold a class `Local` that
  inherits `Greeter`. Before the fix both called `Local.words` on the
  library's object (`s10-plugin-red.log`, `s10-named-red.log`).
  `tests/dump/devirt_plugin.opt` pins the plugin side: the call of
  `talk` read `call i64 @devirt_plugin.Dog.speak` before the fix, and
  reads the table now. The audit names an abstract class. The fix
  covers every class that is not final, because a plugin may inherit a
  concrete class and replace its function, which is the same gap.
- S29. antic refuses `--no-hooks` for a program that loads libraries,
  naming both, as Eddie decided. `tests/errors/no_hooks_plugins.anti`
  pins the message. It also refuses `--no-hooks` with `--no-runtime`.
  A probe before the fix showed why (`s10-nohooks.log`): a host built
  with `--no-hooks` still counted the objects of a library built with
  its hooks, since the `created` and `destroyed` sites of a class stand
  in the code of its own module. A normal host that loaded a library
  built with `--no-hooks` crashed with status 139, in `delete` after
  `unload`. The refusal of the host alone would have left that crash.
  `tests/run_plugin.cmake` checks both refusals and that a closed host
  still builds with `--no-hooks`.

`tests/emit-identity/programs.sha256` was written again for
`inject_default`, whose table calls stay indirect now, six files.

## Provisional entries

- Under "Plugins" in `docs/decisions.md`: a release build of a program
  that can load a library, and of a library, makes no table call direct.
- Under "Hooks and tracing": a plugin cannot be built with `--no-hooks`.
