# Fix step 35, the remaining malformed-input tests of M43

Step 35 of "Fix steps" in `docs/audit/summary.md` adds the remaining
malformed-input tests of M43. They cover the plugin index, a
configuration that is no TOML, and the Mach-O symbol table and debug map.
They also cover the command-line splitter, `read_source` with a NUL, and
a truncated COFF object and archive index.
Logs are in `build/drive/logs/s35-*`.

Status: green and pushed.

## Findings

| ID | Result |
|---|---|
| M43, `read_source` with a NUL | Fixed. `error_source_nul` puts a NUL at the start, inside the first block of 4095 bytes, at its last byte, at the first of the next and at the end. The reader was right. |
| M43, command-line splitter | Fixed. `test_utf` adds lines that end in backslashes, open quotes, empty and doubled quotes, tabs and blank lines. It also splits every line of up to six units into a buffer of exactly the promised room. The splitter was right. |
| M43, configuration that is no TOML | Fixed. Six `conf_*` cases: plain text, a cut string, an open table header, a key without a value, the same through an include and through `rt.configure`. The runtime was right. |
| M43, Mach-O symbol table, debug map and object lines | Fixed, with one defect. A damaged object entry left the functions after it on the object before it. A damaged function start left the function before it open (`s35-red-macho.log`). |
| M43, truncated COFF object and archive index | Fixed, with one defect. The size field of an archive member went through `strtoul`, so `+108`, ` 108`, `108x` and `108 1` read as 108 (`s35-red-archive.log`). |
| M43, plugin index | Fixed, with three defects (`s35-red-plugin.log`). An index path that held a NUL loaded the library its first bytes named. `plugin.load` did the same. An interface listed after 64 others was never found. |

The other readers of M43 belong to other steps.

## Tests first

Each defect above showed in its test before the fix: three checks of
`macho_debug_map`, four size fields of `test_archive_index`, and three
cases of `rt_plugin_table`. The rest of the new tests passed on the code
as it stood. Two expectations of my own were wrong, and I changed them
before any fix. Six symbols still fit inside the test file, and `[]` is
TOML.

Every new reader test of C works on a copy of exactly the size it reads.
The ASan suite then checks each read and write against the end.

## Fixes

- `anti_rt_macho_debug_map` treats an entry whose name lies outside the
  names as what it would replace. An object entry gives no object, and a
  function start gives no name.
- `member_at` of `coff.c` reads the size through `member_size`, digits and
  then spaces alone.
- `path_of` of `plugin.c` refuses a path with a NUL. `plugin.load` says
  so, and discovery passes over such an entry. `index_lists` walks the
  whole list.
- `link_identity_macos-arm64` failed on the first host run, because
  `return42` links the changed runtime. The digest file holds the one
  this Mac gives, as the test asks (`s35-host-ctest.log`).

## Left

`anti symbols` reads the path of an index entry as a C string in
`src/anti/syms.c:385`, so a path with a NUL names the file before it
there too. The walk is the copy of the runtime's that the major finding
on `syms.c:312` names, and the step that removes that copy owns it.
