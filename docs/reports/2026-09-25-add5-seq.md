# The sequences of round five: BLOCKED at `==` on a list

The step builds `List<T>`, `Deque<T>`, `Ring<T, N>` and `Grid<T>` in their
modules of "Module layout of the collections". It stopped after `List<T>`,
because `==` on a list needs a change to the compiler, which lies outside the
fence of the step.

## What was done

- `src/std/anti/collection/list.anti` holds `List<T>` with every operation of
  "Sequences" and the operations every collection has. Beside the base, that
  is `new(capacity, from)`, `push`, `pop`, `insert`, `remove_at`, `l[i]` and
  `l[i] = x`. It is also `get`, `first`, `last`, `read`, `modify`,
  `lend_slice`, `sort`, `sort_by`, `reverse`, `map` and `filter`. `reserve`,
  `shrink`, `for` in both forms and `pub operator fn eq` complete it.
- `tests/std/collection_list.anti` and its `.expected` run each operation
  and the room under a counting allocator. A list of a class whose `destruct`
  counts its calls tears every element down once, 13 made and 13 torn. A list
  of pointers leaves its three objects alive.
- `docs/decisions-seq.md` holds the decisions, each `[provisional]` one with
  its reason.
- Not done: `Deque<T>`, `Ring<T, N>` and `Grid<T>`, the dev-mode run of the
  test, the check of the change count in `tests/checks/`, the gates.

## The blocker

`a == b` on two lists of another module is refused with `` `==` is not
defined on `List<int>` ``. The same happens with a small generic class and its
`pub operator fn eq<T: eq>` in any library file, while `a.same(b)` through a
plain generic function of that module works.

`read_declaration` of `src/antic/antl_tree.c` makes a new item for a generic
function and links the symbol to it, and the declaration carries no
`is_operator`. `symbol_is_operator` of `src/antic/sema_expr.c` reads the mark
from the item when there is one, so the mark the symbol read is lost.
Carrying the mark in the declaration, with a new format version, or taking it
from the symbol there, would fix it. Every collection of round five gets `==`
this way, so the maps and sets meet the same refusal.

## Other defects found, each with a way around it

- `-t.number()` is refused with `` unknown name `Tag.number` ``, and
  `0 - t.number()` is accepted. It holds outside any generic.
- A lent slice passed to a `lent` parameter of a generic function is refused
  with `` `xs` is lent for the call and passes on to a `lent` parameter
  alone ``. The sort therefore runs in the public `sort_with`, over a plain
  slice.
- `list.List<int>.new()` and, inside the body of `List<T>`, `List<T>.new()`
  are refused with `` nothing in the arguments gives `T` of `List` ``. A
  direct import and a literal work.
- A library file carries no function of a class with type parameters of its
  own, as `CLAUDE.md` says, so `map` and `sort_by` are functions of the module.
