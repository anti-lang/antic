S02. `fixed_layout` refuses the unit break `_` and the word of a Mutex,
so `as` between a simd struct and a struct holding either is an error.
The probe of the tool pass and the Mutex case of `back-end` both
compiled before the fix. `docs/notes/simd.md` names the two refusals.

S09. `check_type_member` gives the base of `E.A`, `K.N` and `m.T.x` the
type it names. Every reader of a field's base then finds a type, and a
name of a type is no place. `&E.A`, `E.A = E.B`, `1 + E.carry` and
`E.A.compare_swap` crashed before. They now give the ordinary messages
of a place and of `+`. Rewriting `m.T` into a name was tried first and
dropped: the checker checks some nodes twice, and a name `T` does not
resolve outside its module. The typed dump of `generics.anti` now shows
the type beside each such base.

S12. `sema_is_place` refuses a field node that names a function, a
static or a constant. `&v.area` crashed in lowering before. The constant
folder refuses the same node before it reads the base. Its message stays
"this field is not a constant expression", as it was while the base had
no type.

S10. The base of an enum must be an integer type, the test the library
reader makes. A named type whose symbol has no type yet, as in `enum A:
A`, is refused in `resolve_type_inner` instead of resolving to NULL.
`enum A: A` crashed before, and a struct, `str` or another enum was
accepted.

S14. `module_function` takes the number of arguments the call passes
and refuses a function with fewer parameters. `call_of` checks each
argument against its parameter quietly, since the call does not check
them again. `tests/modules/anti/regex.anti` is a damaged `anti.regex`.
Before the fix, `error_regex_damaged` printed a count wrapped to
18446744073709551613 after reading past the parameters.

M44. `patch_group` compares the literal as a u64 with the group count
before narrowing it to `int64_t`. `pattern.h` returns its counts as
`int64_t`. `error_patch_group_wide` passed before the fix on the Mac,
whose `long` is 64 bits. It shows the defect only on a Windows host.

S15, S16. The dump prints the literal of `alloc T { }` and the type and
count of `alloc(T, n)`. `label_name` prints no text for an empty name.
`dump_ast_alloc_loops` and `dump_types_alloc_loops` crashed before the
fix. The S16 half of the test cannot fail before the fix: no libc of the
six targets reads a `%.*s` of precision 0. It pins the output.

Before the fix, the unit tests segfaulted in `test_sema_members`, and
the dump and damaged-library tests failed
(`s7-unit-before-fix.log`, `s7-ctest-before-fix.log`).

## Seen in passing and left

  with "`K` has no function `t`". The behaviour was the same before this
  step.
- `enum A: B` before `enum B` says "unknown type `B`". The front-end
  report predicted a NULL base here instead.
- `m.18446744073709551617` names group 1, as `front-end` notes among
  the minor findings at `sema_pattern.c:681`. That is step 40.
- A class constant `K.N` is not a constant expression, as before.
