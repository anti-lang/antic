# Fix step 12: runtime shared state

Step 12 of "Fix steps" in `docs/audit/summary.md` names S33, S34, S35,
M19, M22 and M30. An earlier run of the step stopped before any code
changed, because S33 and S34 need `src/rt/backtrace.c` and
`src/rt/registry.c`. The task now lets a fix change the other side of a
lock in the same area, so both files changed with their findings.

## Findings

- S33, fixed. One lock in `conf.c` guards the value, source and layer
  of every key. A replaced value is kept on a list until the program
  ends. `anti_rt_option_backtrace` is stored atomically in `conf.c` and
  loaded atomically in `backtrace.c`. A second `rt.configure` returns
  at once while the first reads. Test: `rt_conf_race`, a C program
  with stand-ins for the loader and `anti.fs`. The runtime of an Anti
  program carries no sanitizer, so an Anti test could not show it.
  ASan reported a heap use after free on every run before the fix.
- S34, fixed. One lock in `loaded.c` guards the slots. Load and unload
  write under it, the `created` and `destroyed` hooks count under it,
  and `anti_rt_registry_find` walks the classes of the libraries under
  it. The count of open libraries stays atomic and outside the lock.
  The check of `live` and the release of a slot share one hold. The
  library is opened and closed outside the lock. The reason of a
  failure is per thread, and Windows writes the text of a failed open
  into the caller's buffer. Test: `rt_plugin_race` loads two libraries
  from two threads at once and fails two loads at once. Before the
  fix, both loads took one slot on every round, and each thread read
  the other's reason.
- S35, fixed. One lock guards `handlers`, `started` and `pipe_ends`.
  The readers copy the function under it and call it after. Test:
  `rt_signal`, eight first registrations at once. It counted four or
  more new files on every run before, and two after.
- M19, fixed. `start_reader` closes both ends of the pipe in one
  cleanup block when `pthread_create` fails. No test makes
  `pthread_create` fail: a limit on threads is per user on Linux and
  has no such effect on macOS. The path was checked by reading it.
- M22, fixed. Under clang the `_MSC_VER` branch loads with
  `__atomic_load_n`, which is `ldar` on windows-arm64. MSVC loads with
  a barrier after it on ARM64. The byte load no longer relies on the
  signedness of `char`. Test: `atomic_load_<target>_<level>` refuses a
  plain load in `anti_rt_atomic_load` of each ARM64 runtime. The three
  windows-arm64 cases failed before the fix. The MSVC branch did not
  compile here.
- M30, fixed. `wake_caller` broadcasts on both platforms. Test:
  `program_parallel_join`, a joiner and the caller of `parallel` that
  wait at once in both orders. It hung until the timeout before.

## Other changes

- `anti_rt_plugin_provider` unloads before it writes its reason. The
  unload used to clear the reason it had written the line before.
- The emit manifest gains the six files of `parallel_join`, and
  `tests/link-identity/return42.macos-arm64.sha256` takes the digest of
  the changed runtime.
- The docs-style checker reports nothing on the touched C, Anti, TOML
  and cmake files. It reads `tests/CMakeLists.txt` as Markdown, as the
  report of step 11 says, and was not run on it.
