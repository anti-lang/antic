# The synchronized collections

Step add5-sync of round five: `SyncList<T>`, `SyncMap<K, V>`, `SyncSet<T>`
and `SyncPool<T>` in `anti.collection.synchronized`. The step stops BLOCKED on
one change outside its fence, under "Blocked" below. Everything inside the
fence is built, committed and green.

## Done

- `src/std/anti/collection/synchronized.anti` holds the four classes, each a
  synchronized class around `List`, `Map`, `Set` or `Pool`, with the
  operations of the plain collection less those by position and `lend_slice`,
  a versioned set on each, and walks that take copies under the lock.
- `tests/std/sync_list.anti`, `sync_map.anti`, `sync_set.anti` and
  `sync_pool.anti` take every operation on one thread under a leak count. The
  four `_threads` programs run `parallel` chunks against one collection, count
  with a loop of a versioned read and `set_if_version`, and show a versioned
  set that fails after a dispatched worker changed the element. Each runs in
  release and dev mode, `tests/CMakeLists.txt` registers the dev runs beside
  those of `anti.collection.concurrent`, and the runs with threads have a
  timeout of 120 seconds.
- `tests/run_anti_check.cmake` counts 35 files of the standard library.
- `docs/decisions-sync.md` holds the decisions, eleven of them
  `[provisional]`, and the defects the step found.

## Failed and fixed

- `return x` into a `?T` from a public function of a synchronized class failed
  the IR verifier. The functions return through plain functions of the module.
- A pair built from an `own` parameter, or from a local, freed the element
  twice in a generic copy, where a plain function refuses it. `push` and
  `set_if_version` copy `x`, and the element comes apart from a call result.
- `self.super.copy(to)` copied the list shallowly, and the bytes of the object
  carry its held lock. `copy` starts from the bytes of an empty object.
- `fn union` at module level does not parse, and `map` clashed with the module
  `map`. The set functions take a plain `Set`, and the module imports
  `anti.collection.map as maps`.

## Not built

- `==` and the hash of the four classes. `==` hands the operator a byte copy of
  a synchronized object with its lock, which hangs when another thread holds
  the lock at that moment. The fix lies in `src/antic/`, and
  `docs/decisions-sync.md` gives the detail.

## Blocked

- `src/std/anti/collection/pool.anti`: `take_place` returns
  `(taken, after)` and `get_versioned` returns `(copy, ...)`, a local in a
  tuple literal. For an owning element the local is torn down when the
  function returns, so `remove_all`, `remove_first`, `remove_one`, `clear` and
  `get_versioned` free the element twice. A `Pool<Id>` with ten elements and
  one `remove_all` stops in `free`. `SyncPool` calls these functions, so it
  frees twice for an owning element as well. `std_sync_pool` takes those
  operations on `SyncPool<int>` alone. The fix builds the pair from the call
  results, `(self.release(at), after)`, which is outside the fence of this
  step.

## Questions
