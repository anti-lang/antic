# Real x86_64 hardware

Item 6 of the session that closes the move to LLVM. `~/.ssh/config` names no x86_64 host
besides anti-linux and anti-windows, so the hardware was the GitHub runners of
`.github/workflows/test.yml`, started twice with `gh workflow run`, the run Eddie allowed
and the one that confirms. The trigger stays `workflow_dispatch`.

## The first run, 37688511333

Every job failed before the suite could say anything about the code:

- macos-arm64 and macos-x86_64 stopped at the configure step. The images carry no macOS
  SDK 26.5, which `tools/macos-sdk-pin` names.
- Both Windows jobs stopped at the configure step. The workflow installed raylib on the
  other runners alone.
- Both Linux jobs failed 633 of 1330 tests. The workflow installed no sysroot, so no
  program test could link. 24 more tests failed under CMake 3.31, which keeps the old
  meaning of `IN_LIST` and of a quoted argument of `if()` in a script that sets no
  policy. CMake 4 of the Mac and the VMs dropped those policies.

local, beside the 11 commits of `../llvm-tools` that `main` holds and `origin` does not.

No third run was made. The fixes after the second run are proven by their tests, by
