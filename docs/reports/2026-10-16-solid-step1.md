# Solid: step 1, the life of a loaded library

The step fixed the four findings of step 1 of "Fix steps" in
`docs/audit/summary.md`: S306, S307, S308 and M303, in one session from
2026-10-15 to 2026-10-16. Each starts with the test that shows it. The logs lie in
`build/drive/logs/`, under names that start with `step1-`.

## Findings closed

Severe first. One sentence gives the cause of each.

| Finding | Commit | Cause |
|---|---|---|
| S306 | `06e06339` | A frame kept its build id, and a Mach-O frame its function name, as a pointer into the image of the module, which `unload` takes away. |
| S307 | `b80a1e46` | `registry_find` gave the lock of the slots back before `reflect.new` and `Object.deserialize` read the descriptor and ran `init` in the library, with no object counted. |
| S308 | `cfa95068` | The `destroyed` hook counted the object off its library, and the teardown writes that hook before every `destruct` and the teardown of the fields. |
| M303 | `3d33cbfa` | A second load of an open library gave the slot of the first without a count, and `claim` looked for a free slot first. |
| T135 | `d3fe0671` | A deserialize that fails ran the teardown of what it built and counted no object off its library. |

`2d5ee0b0` writes the commit of each into its row of the summary, and
adds the row of T135 to `docs/audit/tests-findings.md`.

- The tests. `rt_plugin_race` loads a library twice, and again with all
  sixteen slots taken by copies of it (M303). `plugin_stages` holds the
  main thread in the code of a library while a worker tries the unload.
  It does so in the `construct` that `reflect.new` runs, in the one that
  `Object.deserialize` runs (S307) and in the `destruct` that `delete`
  runs (S308). Its last line is T135. `plugin_trace` takes a trace in a
  library, unloads it and reads the frame again (S306). Each failed
  before its fix. M303 failed four checks, S307 and S306 ended in a
  segmentation fault, S308 closed the library, and T135 gave `alive 1`.
- S308 needed no change of the order of the hook in `lower_owning.c`.
  `anti_rt_delete_from` counts the object off once the teardown and the
  free have returned, and the hook no longer counts. Every `delete` of
  generated code calls it.
- S306. `known[]` of `trace.c` keeps a copy of each id as well. It still
  keys the id by the address of a header. A library that a later load
  maps at the same address is then named by the id of the first. The id
  is wrong, and no freed memory is read. No test can place two libraries
  at one address, so it has no row and no line.
- The step changed the runtime that every program links, so
  `link_identity_macos-arm64` takes the new digest of `return42` in
  `5f255a14`. `emit_identity` is unchanged.
