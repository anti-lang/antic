# The fix of T209, the names of the parts of a class

Eddie's order of 2026-11-08 asks for the fix of T209. A function of a class
body named `init` took the symbol of the init function the compiler writes
for every class. "Classes" in `docs/anti-syntax-overview.md` reserves no name
of a function, so the compiler's own symbol moves.

## T214, the fuzzer's object of `anti.lang`

The first host suite with the fix of T209 failed `fuzz_smoke` alone. Every

`_other_key` and `_same_key`. The first two failed before the change with

`ubsan` under the commit of T209. The grade is `minor`, as T138, the other

## The defect of T209

The three tests of T209 failed for its reason before the change. antic
stopped with `internal error, the IR of ... fails verification` and
`classes_function_named_init.Counter.init b0: ret void in a function that
returns i64`. The init the compiler writes and `pub fn init(self) -> int` both
had the symbol `<module>.Counter.init`.

## The new symbol

The parts of a class are `<Class>.<part>:written`, `Counter.init:written`.
`LOWER_WRITTEN` of `src/antic/lower_lowerer.h` holds the mark, and
`lower_class_part` of `src/antic/lower_desc.c` writes every such name. The
name of the copy of a chain that declares `copy` came first:
`Class.copy:written`, since the declared one is `Class.copy`. A name a program
writes holds a `:` only as `<operator>:<Type>` of an operator at module level,
with no `.` before it, so no function or static of a class can take a part.
The LLVM text writes the `:` as `$3a`, the escape that the `<` and the `>` of a
copy of a generic already take, so the symbol in an object is
`Counter.init$3awritten`.

Three groups of names stay:

- The teardown, the copy, `equals` and `hash`, `Class.destroy` and the others
  of "Object model" in `docs/decisions.md`. Each fills the entry of the root's
  table of its name. `destroy` is a keyword, a class declares the other three
  only as that entry, and the compiler writes `equals` and `hash` only for a
  chain that declares neither.
- The C names of an export class, `anti_<Class>_init`, `anti_<Class>_vtable`
  and `anti_<Class>_descriptor`, and the table and the descriptor of each
  sub-object of an interface, `Circle_dr_table`. These are exported, and a
  `:` makes no C identifier. The C header does not change.
- The descriptors of a struct, a `?T`, a tuple and an array. A struct has no
  member that is a symbol, and the other three already hold a `?`, a `(` or a
  `[` in their names.

## The other parts

Each part a class can hold was checked with a function of that name, on the
Mac, before the change:

| Part | Kind of class | Before the change |
|---|---|---|
| `init` | every complete class | internal error, T209 |
| `descriptor`, `fields`, `functions`, `ancestors` | every class | opt: redefinition of global |
| `instance` | a singleton | opt: redefinition of global |
| `type_args` | a copy of a generic | opt: redefinition of global |
| `chain`, `versions` | an abstract class | opt: redefinition of global |
| `table` | every class | refused, `Object` has a `table` |
| `copy`, `equals`, `hash` | every class | refused without `concrete` |

A static atomic named `descriptor` compiled, and its `load` and `store`
reached the descriptor of the class. The program stopped with `Bus error`.
These are the defect of T209, so the fix covers them, and five matrix programs
show them:

- `classes_functions_named_as_the_data_of_the_class`
- `classes_singleton_function_named_instance`
- `classes_generic_function_named_type_args`
- `classes_abstract_functions_named_chain_and_versions`
- `classes_static_named_descriptor`

Each failed in its three modes before the change and passes after it.

Two other clashes are defects of their own, each with a row and three lines of
`tests/known-failures.txt`:

- T215, major. `<module>.patterns.start` is the function that compiles the
  pattern literals of a module, `IR_PATTERNS_START` of `src/antic/ir.h`, and a
  function `start` of a class `patterns` takes it. opt refuses the program.
  The name is one per module, not per class. Its program is
  `classes_function_named_start_of_a_class_named_patterns`.
- T216, severe. The descriptor of the sub-object of `implements s: Shape` is
  `Circle.s.descriptor:written`, and so is the descriptor of a class `s`
  nested in `Circle`. antic builds the program, and it stops with `Illegal
  instruction` in dev mode and `SIGTRAP` in the other two. The full name of
  a nested type and the name of a field meet there, with no function of the
  program involved. Its program is
  `classes_nested_class_named_as_an_interface_field`. The thunks,
  `Circle.s.area.thunk`, stand under the same path. No program here reached
  a class nested two deep to show it.
