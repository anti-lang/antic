# Fix step 13: runtime plugin table and `Object.deserialize`

Step 13 of "Fix steps" in `docs/audit/summary.md` names S38, M10 and S32
in `src/rt/plugin.c` and `src/rt/registry.c`. S32 follows Eddie's answer:
`serialize` writes `null` where the object does not own a pointer, a
slice or a function pointer, and `deserialize` takes nothing else there.
The writer of that form is `put_value` in `src/rt/object.c`, the other
side of the reader, so that file changed with it.

## Findings

- S38, fixed. `damage_of` in `plugin.c` checks the table
  `anti_rt_provides` before the loader reads a value of it. It covers
  every length, text and count, each descriptor, the size of a class,
  the offset of the sub-object and the version chain. A damaged table
  refuses the load, and the message names the damage. A version part
  compares by its digits, so 20 digits no longer overflow. Test:
  `rt_plugin_table` loads `tests/unit/plugin_bad.c` with one value
  damaged at a time, and compares long version parts. Before the fix it
  printed bytes past the end of a version text and then crashed with
  signal 11, see `build/drive/logs/s13-s38-red.log`.
- M10, fixed. `fill` keeps one bit per field of the chain, and a member
  whose field was read already fails the whole text. Test: two new texts
  in `std/deserialize_undo.anti`, a repeated `own` member and a repeated
  `str`. Before the fix the first came back as an object with three
  blocks still lent.
- S32, fixed. `put_value` and `put_slice` write `null` for a pointer, a
  function pointer and a slice the object does not own. `read_value`
  takes `null` there and fails on anything else, and `read_view` is
  gone. Test: `std/serialize.anti` checks the null forms after a round
  trip and refuses an address for each of the three kinds. Before the
  fix the test failed on the written text.

The commit of M10 carries the `registry.c` half of S32 too, since both
changed the same functions and the tools allow no partial staging.

## Decisions
