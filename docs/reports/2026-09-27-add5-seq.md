# The sequences of round five

The step builds `List<T>`, `Deque<T>`, `Ring<T, N>` and `Grid<T>` in their
modules of "Module layout of the collections". The first run stopped at `==`
on a list, as `docs/reports/2026-09-25-add5-seq.md` reports. Commit `3eb10e5`
on main keeps the operator mark of a generic in the library file, so that
test now passes unchanged, and this run built the rest.

## What was done

- `src/std/anti/collection/deque.anti`: `Deque<T>`, a ring buffer that grows,
  with `push_front`, `push_back`, `pop_front`, `pop_back`, `front`, `back`,
  `new(capacity, from)`, `reserve` and `shrink`.
- `src/std/anti/collection/ring.anti`: `Ring<T, N>` with `push(own x) -> bool`,
  `pop`, `peek` and `is_full`. It takes room for `N` once, in `new(from)`.
- `src/std/anti/collection/grid.anti`: `Grid<T>` with `new(width, height,
  fill, from)`, `g[x, y]` in both directions, `get(x, y)`, `width`, `height`
  and `lend_slice`, stored row by row.
- Each has the operations every collection has, an iterator that lends each
  element, `==` through `collection.equal`, and a `copy`. `List<T>` gained
  the same `copy`: `dup(&l)` shared the room and freed it twice.
- Tests: `tests/std/collection_deque.anti`, `collection_ring.anti` and
  `collection_grid.anti`, and `dup` in `collection_list.anti`. Each covers
  every operation, a class whose `destruct` counts its calls, a collection of
  pointers that leaves its objects alive, and `Iterable<int>`. All four run in
  both modes. The ring's test counts allocations. There is one for the ring,
  across a thousand turns, the walks and every operation that makes nothing
  new. `find_all` and `dup` then take one each.
- `tests/checks/list_changed.anti` holds the change-count trap of a list.
  `list_bounds.anti` and `grid_bounds.anti` hold the index traps, the second
  a column past the width that a check on the whole buffer would miss.
- `tests/run_anti_check.cmake` counts 30 files of std, the four modules added.
- `docs/decisions-seq.md` holds the decisions.

## Failures and fixes

- `anti_check` failed at 26 files of std. The count was raised to 30, as
  `2c768ee` did for the three earlier modules.
- `fmt_canonical` refused the wrapping of five files. `anti fmt` wrote them.
- `Ring<T, N>.new` crashed, see the first defect below. The result is bound to
  a local first.

## Defects outside the fence, each worked around

- `b.p = some() catch fatal;` with `b.p` a `?*int` field compiles to a call
  through the table of the result and a store of a 32-bit zero, and crashes
  in a program of ten lines as well. `let` then `=` works.
- A value that owns nothing, an `int` or a plain struct, is refused after it
  is passed to an `own` parameter: `` `i` was moved into `at_back` by
  `push_front` ``. The tests build each value afresh.
- A trap inside a copy of a generic from a library file names the file of the
  program with the line of the library. `list_bounds.anti:281` points at
  `slot` in `list.anti`. The bound patterns leave the file open.
- `dup(l)` of a collection value is refused, `` `dup` needs a class pointer
  ``, so "Principles" copies by `dup(&l)` alone.
- `Copies<T>`, `PriorityQueue<T>`, `Pool<T>` and `Tree<T>` have no `copy` of
  their own, so `dup` of one shares its room as a list did. `deserialize` of
  a collection is not built in the shared parts.

## Provisional decisions

Each stands in `docs/decisions-seq.md` with its reason: the `copy` of each
sequence, the ring layout of `Deque<T>` and its lack of an index, the room of
`Ring<T, N>` taken once in `new` with `N` below 1 stopping there, the extra
slot of `Grid<T>` for the fill value and its dimensions clamped at 0, the
remove forms and `clear` of a grid putting the fill back, the check of each
grid index against its own dimension, and `==` of grids needing one shape. The
decisions of the first run about `List<T>` stand unchanged.
