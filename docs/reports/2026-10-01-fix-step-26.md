# Fix step 26, antic platform layer

Step 26 of "Fix steps" in `docs/audit/summary.md`: M30 and M31 for
antic, and the minor path rules. `src/antic/platform.c` and `platform.h`
are now the one platform layer of antic. `selfpath.c`, `selfpath.h`,
`process.c` and `process.h` moved into them and are gone. `target.c`,
`userdirs.c`, `applesdk.c`, `driver.c` and `main.c` call the layer, and
seven files of `src/anti/` include `../antic/platform.h` in place of the
two old headers. Logs are in `build/drive/logs/s26-*`.

Status: green and pushed.

## Findings

| ID | Result |
|---|---|
| M30, antic | Fixed. The 18 host `#if` lines of `src/antic/` outside the layer are gone. `platform.c` defines `target_host`. `user_dir` and `apple_clt_sdk` ask `target_host` for the system, and the SDK directory is read with `platform_list_directory`. The link of `driver.c` takes its separators from `platform_last_separator` and `platform_separator`. The new test `platform_layer` refuses a host `#if` in any other file of `src/antic/`. It failed on the tree before the change and passes after it. |
| M31, antic | Fixed. The layer holds paths, arguments and variables as UTF-8 and calls the UTF-16 entry points of Windows: `_wfsopen`, `_wremove`, `_wdupenv_s`, `GetFileAttributesW`, `FindFirstFileW`, `GetFullPathNameW` and `CreateProcessW`. `main` of antic reads its arguments again through `_configure_wide_argv`. `anti`'s own `main` and `files.c` are step 28. |
| Path rules, minor | Fixed for `path_is_absolute`, `self_directory`, `parent_of` of `userdirs.c` and `copy_memcheck_dll` of `driver.c`. They follow the rules of the runtime through `platform_last_separator`, so a backslash separates on Windows alone, and `C:x` is absolute there. `tests/unit/path_rules.h` holds the cases, and `rt_platform` and the unit tests of the tools both run them. |
| Path rules, `files_base_name` | Not a defect. `docs/decisions.md` holds a `[provisional]` entry that it takes both separators on every host, so that a path naming a Windows directory splits the same way on the machine that reads it. `syms.c` reads such paths from a configuration and an archive. The entry is binding, and the function is unchanged. |

## Decisions

Three `[provisional]` entries under "Repository layout" in
`docs/decisions.md`:

- the platform layer of antic is `platform.c` with `platform.h`, which
  defines `target_host`. `process_run_lines` stays POSIX alone, under
  one `#if` of `platform.h`.
- the tools hold UTF-8 and convert to UTF-16 at every call of Windows,
  and antic's arguments come from `_configure_wide_argv`.
- the path rules of the tools are those of the runtime, and
  `files_base_name` keeps its own entry.

Two entries were brought up to date: the one on `platform_open` names
`_wfsopen` and `_wdupenv_s`, and the one of `anti symbols` names
`platform.c` in place of `selfpath.c`.

## The Windows VM

The full suite ran on anti-windows in two parts (`s26-vm-suite-1.log`,
`s26-vm-suite-2.log`). Of 1140 tests, 1128 passed, 8 skipped and 4
failed. None of the four comes from this step:

- `repo_layout`: a file `s37probe.cmake`, left in the tree of the VM by
  an earlier session, stands at the top level.
- `fmt_canonical`: the command line of `anti fmt --check` over 671
  sources is 39386 characters, past the 32767 that Windows takes. CMake
  reports `name too long` before anti runs (`s26-vm-fmtprobe.log`).
- `memory_checks` and `trace_forged` fail the same way at `b487b624`
  (`s26-vm-head-test.log`). windows-arm64 refuses `--memory-checks`,
  and `forged` ends with `0xc0000409`.

## Questions

- `fmt_canonical` cannot pass on Windows while the sources need more
  than one command line. A list file, or one call of `anti fmt` per
  directory, would fix it, and the choice is open.
- `memory_checks` runs on a windows-arm64 host, which refuses the
  option by design. It needs a skip there.
