# Fix step 17, owning values in lowering

Step 17 of "Fix steps" in `docs/audit/summary.md`: M05, M14 and M48 in one
file with one predicate, and the minor finding on the loops over array
elements. The files are `lower.c`, `lower_stmt.c`, `lower_expr.c` and the new
`lower_owning.c`. The fix also needed `lower_lowerer.h`, `lower_eq.c`,
`lower_hash.c` and `tools/sources.cmake`. Logs are in `build/drive/logs/s17-*`.

Status: green and pushed.

## Findings

| ID | Result |
|---|---|
| M05 | Fixed. `lower_owning.c` holds the one teardown, copy and clear. A local, an `own` or `keep own` parameter, the old value of `=`, a temporary and a dropped result take `lower_destroy_owned`, gated by `sema_needs_teardown`. `destroy_value`, `destroy_array`, `destroy_optional`, `lower_clear_tables`, `lower_needs_teardown` and the snapshot exit action are gone. A class value goes to its `destroy` after the table check, as a local and as a field. The fields of a class go last to first. `teardown_field` and `copy_field` take the one teardown and copy, so the `?Class` copy checks its table. `lower_copies_parts` says why it reaches more than a teardown. |
| M14 | Fixed. `lower_prepare_object` writes the tables, the fields of a literal and the defaults. A literal, `T(args)`, the class init and the singleton's `get` all call it. |
| M48 | Fixed. An `own` pointer or slice whose element owns something tears down and copies each element with the one teardown and copy. A pointer to a class keeps `anti_rt_delete_from` and `anti_rt_dup`, since the object may be of a class below. |
| Minor, loops over array elements | Fixed. `each_element` is the one loop. `lower_array_count` is the one count, which `lower_eq.c` and `lower_hash.c` call. |

`anti_rt_destroy_elements` and `anti_rt_copy_elements` of `src/rt/object.c`
have no caller left. The runtime is outside this area, so they stay for the
step that takes `src/rt/`.

## Tests first

Each test failed on the compiler before the change
(`s17-red-all.log`, `s17-red-locals.log`, `s17-red-buffers.log`,
`s17-red-defaults.log`), and passes after (`s17-green-1.log`).

- `programs/owning_locals.anti`, new, release and dev. A `[2]?Res`, a
  `?[2]Res`, `=` into a `[2]?Res` and an `own [2]?Res` parameter ran no
  `destruct` before. A struct and a class with two fields printed their
  teardowns in opposite orders.
- `programs/owned_buffers.anti`, new, release and dev. `own p: ?*Pair`,
  `own s: []Pair` and `own o: []?Res` tore down no element. `dup` shared what
  the elements own: 4 tags instead of 8, and -4 at the end instead of 0.
- `std/object_defaults.anti`, new. The singleton printed `1 1 0` for the
  bitfields where every other path prints `5 1 9`. Its `own fn` field held
  the bytes of `malloc`. The test aborts with `MallocScribble=1`
  (`s17-red-defaults-scribble.log`). macOS zeroes a freed block, so the plain
  run shows only the bitfields.

## Provisional entries added

In `docs/decisions.md`, under "Files of lowering":

- `lower_owning.c` holds the owning values, and every teardown takes
  `lower_destroy_owned`, gated by `sema_needs_teardown` alone.
- The fields of a class are torn down last to first, the concrete level
  first.
- An `own` pointer or slice tears down and copies what each element owns.
  A copy of a run of elements goes last to first.
- Every new object is prepared by `lower_prepare_object`.
