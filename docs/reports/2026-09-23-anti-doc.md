# anti doc

The documentation generator of `docs/tooling.md`. User docs from a library file
alone, dev docs from the source with `--dev`, the four doc markers, the Markdown
subset, plain semantic HTML with a fixed set of class names and no styling, and
`--markdown`. The doc-equivalence test of the table in `docs/tooling.md` runs.

## What was built

- `tools/anti/doc.c` and the `doc` command of `tools/anti/main.c`. One page per
  module and an index of them, into `-o`, with `build/doc` as the default.
- `driver_interface` of `src/driver.c`. It reads a source file or a library file
  and gives one `struct interface` back, with the syntax tree of a source. User
  docs render the interface, whichever of the two the run was given, so the
  doc-equivalence test measures the library file and not the renderer.
- The library file carries the parameter names of a function of a class body and
  the `worker` mark of a function. Both are what a page prints, and a page
  built from a library file had `a0` and `a1` and no `worker` without them. The
  format version is 51.
- `tools/anti/units.c`. The modules of a run and the order the imports ask for,
  which `anti check` held alone. `anti doc` writes the interface file of every
  source into a work directory before it renders, so a module of the project
  that imports another resolves it.
- `tests/doc` and the test `anti_doc`, which covers the pages of the fixture,
  the doc equivalence, the Markdown form, the developer's page, `--private` and
  the refusal of a library file under `--dev`.
- The entries under "The doc command" in `docs/decisions.md`,
  `docs/notes/doc.md`, the tooling page and the state in `CLAUDE.md`.

## What failed and how it was fixed

- `antl_scale` and the `unit` test held the bytes of a library file, which the
  format version and the member parameter names changed.
  `tests/modules/scale.antl.hex` and the array of `tests/unit/test_modules.c`
  were written again.
- The first run of the generator printed empty names. The names of an interface
  built from a source point into the source bytes, which `driver_interface`
  freed. It now copies the source into the memory pool before the lexer runs.
- The first signature of a function of a class body read the names out of a
  `struct param` array through a `struct name` pointer. Every name after the
  first was then garbage, and the run crashed. The collector builds the list of
  names itself.
- `worker fn` stood on the page of a source and not on the page of its library
  file, which the doc-equivalence run caught. The file now carries the mark.
- `raw_output` refused two `execute_process` calls of `tests/run_anti_doc.cmake`
  that captured output without `ENCODING NONE`. Both were given it.

## Provisional entries

Added to `docs/decisions.md` under "The doc command", where `docs/tooling.md` is
silent. They are the eight class names of the HTML, what a signature carries and
the constants that print a value. Then `anti.lang.Object` left out after
`inherits`, the fields a struct shows against the fields a class shows, the rule
a backtick name resolves by, the work directory, and the files the command takes
without an argument.

## Open

- A signature carries no default value and no `own` mark. The library file keeps
  both for a module-level function and neither for a function of a class body.
  A page cannot print them on both sides yet.
- A backtick name of a developer page resolves against the public interface, so
  a private item of the documented module is no link. The dev collector reads
  the syntax tree and the link tables read the interface.
- `anti doc` on the sources of `std/` needs the flag that lets a module path
  start with `anti.`, which only `antic` takes today. The reference of the site
  is built from the runtime archive's library files, which works.
