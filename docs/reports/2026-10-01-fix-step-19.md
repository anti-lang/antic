# Fix step 19, the rest of the split of lowering

Step 19 of "Fix steps" in `docs/audit/summary.md`: M11, M45 and M49, in
`lower.c`, `lower_expr.c`, `lower_stmt.c` and `lower_desc.c`. The fix also
needed nine new files of lowering, `lower_lowerer.h`, `lower_owning.c`,
`tools/sources.cmake`, `src/rt/mem.c` and `src/rt/std.h`. Logs are in
`build/drive/logs/s19-*`.

Status: green and pushed.

## Findings

| ID | Result |
|---|---|
| M45 | Fixed. `ir_store` read `l->b` beside `lower_converted`, so `let x: ?int = a + b;` failed verification on the Mac. Each call that can change the block or the function is bound to a local first: the value of a `?T`, the code of an `own fn` default, the `parallel` thunk, the reach thunk and the interface table. A scan of every argument list of lowering against the functions that write `l->b` or `l->f` finds no other. |
| M49 | Fixed. `lower_new_memory` calls `malloc` for `alloc T { }`, `alloc T(args)` and the first `get` of a singleton, and a null result calls `anti_rt_out_of_memory`. `to_slice` grows its room with `anti_rt_grow`, which tests `realloc` the same way and takes a size of zero. `alloc(T, n)` keeps `malloc` and `calloc` and gives `?*T`, as the specification says. |
| M11 | Fixed. Each file of lowering holds one part, which `lower_lowerer.h` names. `lower.c` calls back into another file 19 times, against 44 before: 16 times from `lower_module`, twice to `lower_sym_of` and once to `lower_static_descriptor`. |

## Tests first

- `programs/argument_order.anti`, new. Before the fix antic stopped with
  "branchov is not the last instruction" in `sum` and `main`
  (`s19-red-ao.log`). It passes after (`s19-green-ao.log`).
- `trap_alloc_literal`, `trap_alloc_construct` and `trap_singleton_memory`,
  new. An object of 2^60 bytes ended each program with a segmentation fault,
  status 139 (`s19-red-alloc_literal.log`, `s19-red-alloc_construct.log`,
  `s19-red-singleton_memory.log`). Each now aborts with `anti: out of memory
  for 1152921504606847000 bytes`.
- `to_slice` has no program test. A value large enough to exhaust the heap
  needs a frame above the 2 GiB an arm64 frame holds, which antic refuses.
- `unit` pins the call of `anti_rt_out_of_memory` for `alloc T { }` and its
  absence for `alloc(T, n)`.

The first fix of M49 called `anti_rt_new` in the runtime. Its frame stood
between `malloc` and the Anti function, and `memory_checks` and
`anti_memory_checks` failed on it (`s19-fail1.log`). The second commit
tests the result where the object is made.

## The split

The code moved by script, unchanged. A function another file now calls
takes the prefix `lower_`, and one used in a single file became `static`.
`emit_identity` passed on the split without a new manifest
(`s19-emit-split.log`), so no program changed on any of the six targets.
The manifest and `return42.macos-arm64.sha256` were written once, for M49
(`s19-emit-write4.log`).
