The session of `build/prompt-no-ci.md`. Eddie decided on 2026-10-08 that Anti uses no
GitHub CI. The Mac and the two VMs now test all six targets, the x86_64 ones of Linux and
Windows under emulation.

## x86_64 under emulation

Before this session no suite ran a linux-x86_64 or windows-x86_64 program, apart from
`windows_addresses` and `distinct_addresses_windows-x86_64`. The block of
`tests/CMakeLists.txt` that ran every program for macos-x86_64 under Rosetta now serves
`ANTIC_EMULATED_TARGET`, the x86_64 target of every arm64 host:

| Host | Target | Emulation | Level | Tests |
|---|---|---|---|---|
| Mac | macos-x86_64 | Rosetta | `v1` | 214, unchanged |
| anti-linux | linux-x86_64 | `qemu-x86_64` 10.2.1, passed as `EMULATOR` | `v3` | 222 |
| anti-windows | windows-x86_64 | the x64 emulation of Windows 11 | `v3` | 222 |

At `v3` the programs of patterns run as well, which Rosetta at `v1` cannot link. The C
files of the four ABI programs compile with the pinned clang for the emulated target,
against the musl headers of the sysroot on Linux and the Windows sysroot of the runtime
archive on Windows. CMake drops a repeated `-isystem` from the options of a target, which
the first run on anti-linux showed, so each include directory is one joined argument. A
linux-arm64 host without `qemu-x86_64` registers no linux-x86_64 program test and says so
at configure. `docs/vm-setup.md` adds `qemu-user` to the packages of the Linux VM.

The runtime of AddressSanitizer for x86_64, run by hand on 2026-10-08:

| Emulation | Result |
|---|---|
| `qemu-x86_64` | every program stops before `main` with `CHECK failed: sanitizer_allocator_primary32.h:293` |
| x64 on Windows 11 | `interception_win: unhandled instruction` for three functions, then `CHECK failed: asan_malloc_win.cpp:235` |
| Rosetta | `memory_checks_list.anti` for macos-x86_64 at `v1` reports its read after free |

On anti-linux and anti-windows `memory_checks_<target>`, `memory_checks_list_<target>`
and `std_builder_room_memory_checks_<target>` link their program for the emulated target
and report themselves skipped through `SKIP_RUN` of `run_program.cmake`, with the reason.
The runtimes of x86_64 Linux and Windows passed on real hardware in the workflow run of
2026-10-08, as `2026-10-08-llvm-closed.md` reports. `docs/decisions.md`, CLAUDE.md,
`docs/vm-setup.md` and `docs/notes/hosts-and-harness.md` record it as the last run on
real x86_64.

## Documents

One entry under "Scope and toolchain" in `docs/decisions.md` holds the decision and
replaces the two entries on CI. The entry on the six hosts loses `macos-15-intel`. The
entries on the runner matrix of `./r` become one, and the entry on `docs/vm-setup.md` and

`docs/vm-setup.md`, `docs/notes/hosts-and-harness.md`, `docs/distribution.md`,
`docs/work-order-release-script.md` and `docs/work-order-completion.md` follow. The
templates `anti-repository` and `anti-library` in `docs/site/build-tool/index.md` and
`docs/distribution.md` stand as they were.
