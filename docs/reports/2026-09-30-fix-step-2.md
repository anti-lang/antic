# Fix step 2: the tree counts and primitives of the library reader

Step 2 of "Fix steps" in `docs/audit/summary.md`: S13, M33, M20 and the
minor rule 3 conversions and wrappers of the tree reader. The logs lie in
`build/drive/logs/s2-*.log`.

S13. The lane count of a shuffle takes 32 bits through `io_count`, and
the format is version 74. `generics_modules` shuffles the 256 lanes of a
simd struct in a generic of `gen` and prints them from the client. Before
the fix the client refused the library file (`s2-red-s13b.log`).

M33. `io_count` reads through `antl_get_count` with the fewest bytes one
element of each list takes, and `read_tree` bounds its six tables by the
fewest bytes of each record. `tree_counts` pokes the count of the
arguments of a call and the count of the table of expressions. Before the
fix both were refused only bytes later, after the allocation
(`s2-red-m33.log`).

M20. `src/antic/antl_io.c` holds the primitives both files read and write
through, and `antl.c` exports its functions of types, values and
libraries under their `antl_` names. One function reads a type index with
or without `ANTL_NO_TYPE`. `antl_verify_extern` in the verifier holds
each extern to the rules of the tables: a function has the type of a
function, a constant its value, and a local or a parameter is never one.
Two damaged trees show it, accepted before the fix (`s2-red-m20.log`).

Rule 3. A signed number is rebuilt from its bits by arithmetic. A line, a
column and a count of loops read as 0 to `INT_MAX`, a format character
as ASCII, and a name as at most `INT_MAX` bytes. A tree with the line -1
was accepted before the fix (`s2-red-r3.log`).

The wrappers and `antl_fail_needs` are gone, and so is `antl_float_bits`,
which nothing called. `antl.c` is 3528 lines, down from 3788 and still
above the threshold of rule 19.

## Provisional entries

One, under "Libraries and runtime" after the entry on the verifier. Every
count is 32 bits and bounded by the fewest bytes of its elements. A name,
a line, a column and a count of loops lie between 0 and `INT_MAX`.
