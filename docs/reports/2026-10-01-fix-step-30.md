# Fix step 30, anti inputs

Step 30 of "Fix steps" in `docs/audit/summary.md`: M39, M40, M41, M42
and M46, in `fmt.c`, `doc.c`, `zip.c` and `syms.c`. Logs are in
`build/drive/logs/s30-*`.

Status: green and pushed.

## Findings

| ID | Result |
|---|---|
| M39 | Fixed. The angle scan of `anti fmt` is one level deeper per type and stops at `PARSE_DEPTH_MAX`, which moved from `src/antic/parser.h` to `src/antic/lexer.h`, a header `anti` may include. A deeper list is no list, and the parser refuses it. |
| M40 | Fixed. The HTML of `anti doc` writes `[text](url)` as a link for `http:`, `https:`, a relative path and a `#` anchor alone. Every other link stays text. `--markdown` is unchanged, as its DESIGN comment asks. |
| M41 | Fixed. `zip_read` refuses entries whose bytes overlap and entries whose declared sizes add up past `ZIP_MAX32`. |
| M42 | Fixed. `platform_open_file` of `src/anti/platform.c` opens a regular file alone, without waiting on a FIFO. `files_read_file` reads through it, and `resolve_binary` of `syms.c` calls it for the object of a debug map. |
| M46 | Fixed. `emitter_free` of `fmt.c` frees the saved brackets of every frame still open when the source ends. |

## Tests first

- M39: `deep_angles` of the new `tests/unit/test_fmt.c` formats lists
  300000 levels deep of `chan`, `*` and `List<`. Before the fix the
  unit program ended with SIGSEGV, status 139 (`s30-red-fmt.log`).
- M46: `open_anonymous` of `test_fmt.c` formats three sources that end
  inside the body of an anonymous function. With the free taken out, the
  ASan unit run reported a leak from `emit_anonymous_open`
  (`s30-asan-red-unit.log`).
- M40: the fixture `tests/doc/src/com/example/shapes.anti` gains a
  paragraph with a link of each kind. With the old `doc.c`, `anti_doc`
  failed and the page carried `href="javascript:alert"`
  (`s30-docred.log`).
- M41: `archive_bounds` of `test_zip.c`. Before the fix all three bad
  archives were read (`s30-red-zip.log`, three failed checks).
- M42: `object_no_file` of `test_syms.c` builds a Mach-O twin whose debug
  map names a directory, a FIFO and `/dev/zero`. Before the fix the run
  hung on the FIFO until a 20 s alarm, status 142 (`s30-red-syms.log`).
  `regular_files` of `test_files.c` checks `files_read_file` directly.

The Windows and Linux halves of the changed files compile under the
warning set against the pinned sysroots (`s30-win-*.log`,
`s30-linux-*.log`). No VM ran this step.

The first host run failed `raw_output`, because `test_fmt.c` did not
include `binary_stdio.h` (`s30-host-ctest.log`). It does now.
