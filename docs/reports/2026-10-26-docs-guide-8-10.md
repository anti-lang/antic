## Findings

No defect showed, and no row went into `docs/audit/tests-findings.md`. One point waits for Eddie, since no document decides it:

- An `operator fn eq` in a class body serves `==` on values, and the `equals` of the class keeps its default. For `Name` of chapter 9, `n == m` is true and `n.equals(&m)` is false. `docs/anti-language-additions.md` makes the operators of a module the `equals` and `hash` of a class "so `equals` through `*Object` agrees with `==`", and `docs/anti-object-model.md` lets a class-body `operator fn eq` stand for `equals` beside a replaced `hash`. A class with that operator and no `hash` compiles. The guide states both as the code does.

## Questions answered from the code

- Does a struct take an atomic field? No, `atomic` marks a field of a class.
- What is a constant argument? An integer literal or the name of a constant. `Row<2 + 1>` and `Row<-2>` do not parse.
- Does a release build keep the copy that `Row<5>.WIDTH` makes? No. The dev object keeps it, and the release object holds no symbol of it.
- Where does a library copy call a private function of its library? Directly, by the symbol that the object of the library defines in dev mode, and in the one module of a release build.
- The runner has no mark for a program of two modules, so the client of "Generics of library files" stands in a `text` block. Its output was taken at this commit, and the tests `modules_generics_*` and `modules_generic_constant_*` build the same forms.
