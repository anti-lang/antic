# Anonymous functions and closures

"Anonymous functions and closures" of `docs/anti-language-additions.md` is
built, apart from snapshots. Logs lie in `build/drive/logs/closures-*.log`.

## What was built

- `fn(params) -> R { body }` as an expression. A parameter, the result and
  `may fail` left out come from the parameter of function type it is passed
  to. One that captures nothing is an ordinary function value.
- Closures capture the locals and parameters they name by reference. The
  context is a record of addresses in the frame, and creating one allocates
  nothing. A closure inside a closure works.
- `keep` and `concurrent` on a parameter and in the list of a function type.
  A parameter that does not keep its argument has a type of its own, the form
  of two words, so the checks hold on both sides. The caller cannot pass a
  closure where a function is kept. The callee cannot store a parameter that
  is not `keep`, and passing one on to a `concurrent` parameter needs the
  mark. A closure at a `concurrent` parameter changes no captured variable
  whose type is not thread-safe, and the message names the variable.
- Two words in the IR, the code and the context, which goes last. The header
  writes a callback and a `void *` context. An `extern fn` takes C function
  pointers alone.
- A worker takes a function value, and a closure only through a
  `concurrent` parameter, for `parallel` and `dispatch` alike.
- The library format rises to 55 for the two flags of a function type.
  `anti fmt` keeps the brace of an anonymous function on the line of its
  signature, and `anti doc` writes the marks.
- `error.on_fatal`, `os.on_signal`, `log.CallbackSink.new` and
  `log.register` store their function and are marked `keep`.

Tests: `programs/closures.anti`, `errors/closures.anti`,
`errors/closures_modules.anti`, `closures_modules_release` and `_dev`, two
unit tests of the IR and of the library file, the fixture of `anti_fmt` and
of `anti_doc`, and a callback with its context in `clib/roundtrip.c` and
`clib/failing.c`.

## What failed and how it was fixed

- The first program crashed on a call to address zero. `f != none` on a
  pair compared its address. Comparisons, `??`, `let ... else` and the guard
  of a pair now read the code (`closures-run1.log`).
- The optimizer split the slot of a pair whose stores and loads named two
  aggregates, the value's form and the parameter's. Every pair now has one
  aggregate `fn(...)`. The verifier of `--dump-opt` found it.
- A captured variable of a `for` lived in a temporary, which the verifier
  refused as a pointer. A captured loop variable now has a slot, which each
  pass writes.
- `unit`, `clib_*`, `failing_modules_*`, `fmt_canonical` and `emit_identity`
  failed at first (`closures-ctest1.log`). The unit sources that pin a C
  function pointer now write `keep`, the C tests pass a context, the golden
  headers and the manifest were written again, and the formatter learned the
  anonymous body.

## Questions

- The specification names `snapshot fn` as the fix in every refusal of a
  closure by reference. The messages leave it out until snapshots are
  built. Should they name it now?
- A default of a field that names a private function does not cross a
  module, so `walk.Button { }` misses `click` in the module test. It
  predates this step.
- The style checker reads every `#` comment of `tests/CMakeLists.txt` as a
  heading. It reported 233 findings before this step and 236 after it.
