# The warning unused-result

The step built C6 of "Compile-time checks of 2026-10-20" in
`docs/decisions.md`. Logs are under `build/drive/logs/checks-c6/`.

## What changed

Commit `a5d84e1c` builds the warning. `warn_unused_result` of
`src/antic/sema_stmt.c` reads every statement that is a call. It warns when
antic knows the function has no effects, so the call does nothing:

```text
`hash` has no effects and its result is dropped, so the call does nothing [unused-result]
```

The analysis of effects of the optimizer is the class of each row of the
runtime functions in `src/antic/rt_abi.h`. No pass reads the effects of a
function body. antic therefore knows three calls without effects:

- The default hash of a value whose parts reach no `operator fn hash` of
  the program, no `hash` of a class and no Regex. Lowering writes it as
  arithmetic, loads and `anti_rt_hash_bytes`, whose row reads its
  arguments alone. `sema_hash_without_effects` of `sema_hash.c` walks
  the parts as `lower_part_of` does.
- `mul_high`, which becomes one instruction.
- An `extern fn` that names a row of the class none or reads its
  arguments, with `willreturn` and a result. `rt_without_effects` of
  `rt_abi.c` reads the row.

The tests came first. Before the check, the front end compiled each of the
seventeen refusals without a word. The matrix holds the default hash of an
`int`, a `str`, a struct, a slice, a variant, a `?T` and a `*T`, and
`mul_high` and a function of the runtime, as `values_unused_result_of_*`.
It holds the warning in a loop, an `if`, an anonymous function, a `defer`,
a handler, a `switch` arm, a function of a class and a generic function,
as `values_unused_result_in_*`. `values_unused_result_of_calls_with_effects`
drops the results of calls that may have effects. They are a function of
the program, a class's `hash`, an `operator fn hash`, a struct that
reaches one and a hash of a type parameter, and it compiles without a
word. `errors/unused_result.anti` holds a dev build and `allow` before a
statement and in a header. `allow_levels.anti` holds `allow` in a release
build. The client of `tests/modules/hashing` drops a hash that reaches the
operator of a library.

## Where it fired

Nowhere in the repository outside the new tests. The front end ran over
every tracked `.anti` file, `scan.log`, and a search of the sources and
the `.md` files for a statement that drops a hash, `mul_high` or a row
without effects found none. The suites build every program of the
release mode, which refuses the warning, and passed.

## Mistakes of the task

None that contradicts a document. The task names the analysis of effects
of the optimizer. That analysis knows the rows of the runtime alone, so
the warning stays narrow, and two provisional entries say why.

## Provisional entries added

Three, after the entries of C5 in `docs/decisions.md`:

- The three calls antic knows without effects. A function of the
  program warns of nothing. Neither does another C function, the `hash`
  of a class or a hash of a type parameter.
- No simd built-in warns. The optimizer counts a vector instruction as
  one with effects, and `load` checks its slice in dev mode.
- The warning names the call alone, whose receiver and arguments still
  run. A copy of a generic checks no statement again, so the warning
  stands once in the generic.
