## What failed, and the fix

- Linux atomics, `clib_shared`, `clib_two`, `clib_loader` and
  `program_platform_linker`: the Linux host built its own runtime with glibc
  headers, no `-O2` and outline atomics. `7c0a805` builds every runtime as
  the cross build and every host with the pinned tools alone. The configure
  step refuses a tool of the host, and `pinned_tools` checks the cache and
  the mark of lld. The Mac had archived with Apple's ar and ranlib, Linux
  had linked with GNU ld, and Windows took llvm-ar and lld-link off PATH.
- The sanitizers of Linux: three leaks of antic (`c8c3487`), `memcpy` with a
  null pointer (`426d452`), a stack buffer read after its return in
  `test_symbols.c` (`334714a`), and a directory that asked `malloc` for
  2^63 bytes (`974396a`).
- `owning_values` crashed on Linux: `alloc(T, n)` of a struct that holds a
  class value gave uninitialised memory to `=`. It is zeroed now
  (`fe28dd1`, `[provisional]`).
- `listing_error_generics` ran out of memory on both VMs, with a copy name
  of 2^32 bytes. The name is cut at 64 KiB (`1cf44c0`, `[provisional]`).
- `emit_identity` on Windows: six calls with two emitting arguments, found by
  the test and a scan of `src/antic/` (`c914c31`, `7c0a34c`).
- The symbols map of an ELF program named no Anti function (`4770109`), and
  `anti build` put no PDB in a Windows archive (`8b0e63b`).
- `tools/get-sysroot.cmake` broke the junctions of both Windows sysroots
  when run as `docs/vm-setup.md` says, and wrote links Windows cannot
  follow (`34e5691`, `74708ad`). All eight sysroots were installed again.
- Windows tests written for POSIX: dev objects named `.o`, `file://C:/`
  URLs, `app.s`, CRLF from `file(WRITE)`, and tool paths without `.exe`
  that skipped 13 checks of the runtime (`51a72f5`, `973e2d5`, `446c9ba`).
  Once they ran, `rt_names` found a selectany value of the SDK's `wchar.h`
  (`4dfd4e2`).
- `anti build` on Windows failed three builds in ten, since Windows held
  the program that had run a moment before. A write now waits up to two seconds
  (`17a37ff`), and `anti_build` passed ten runs of ten.
- `rt_conf_race` failed once under ASan on Linux: its reader could stop
  before a read of the new value (`9f6a5ed`).
- `anti bind` on Windows: escaped line markers lost every macro of a header
  (`ea57781`). The C side of `clib_simd`, and of every clib test on Windows,
  took the MSVC `arm_neon.h` before clang's own (`8b994aa`). An empty CodeView
  subsection made lld-link warn (`ce7eedb`).

## Process

A reset of the working tree was refused as destructive, so each series of
commits was built in the index from one saved patch. The full host suite
ran on the final tree of each series and not on each commit. The first
sanitizer run on the Mac overlapped a second one I had started by mistake,
and was run again alone. `anti_build` failed once on the Mac and passed 26
runs after it.
