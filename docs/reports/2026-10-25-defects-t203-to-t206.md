## Fixes

| Finding | Commit | What changed |
|---|---|---|
| T204, T205 | `a2a95f61` | `sema_check` declares the symbols of the constants of class bodies before the values of the enums. The bare name `ROWS` in a nested enum is known, and `Table.ROWS` folds to 3 where it read 0. |
| T203 | `e3b57898` | A value of `take(x.f)` stands only where a new owner takes it over: the value of `let`, `if let`, `=` and `return`, an argument of an `own` parameter, inferred or not, and a part of a literal. `sema_check_kept` marks those values, and `take` refuses any other. |
| T206 | `cfff9eee` | An enum value that names a value of an enum declared later, directly or through a constant of a class, has that enum's values declared where the name reaches them. Two enums whose values name each other get `` `First` depends on itself ``. |

T206 is new. A probe of T205 named `Later.X` from an earlier enum and got
`` `Later` has no value `X` ``, since the enums were declared in the
order of the text. It is a major finding, recorded fixed in the same
commit as its two tests.

The T203 rule replaces the test of the whole statement. The 19 probes of
Q17 of the review give the same results as before, apart from p07 and
p08. Those two, a `take` in a condition and one passed to a parameter
that is not `own`, are now refused. `delete(take(h.head))` is refused as well,
since `delete` is not among the owners. `h.head = none` does the same.
