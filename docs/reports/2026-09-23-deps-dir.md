# Pinned downloads from another directory

## What changed

`tools/deps-dir.cmake` takes the directory of the pinned downloads from the
cache variable `ANTI_DEPS_DIR` when it is set and not empty, and keeps
`build/deps` as the default. A script run with `-P` takes the same name as
`-DANTI_DEPS_DIR`. The configure step, `tools/pinned-compiler.cmake`, the
sysroot and raylib paths of `CMakeLists.txt` and `tests/CMakeLists.txt`, and
every `get-*.cmake` script that includes the file follow it. `README.md` and
the entry under "Repository layout" in `docs/decisions.md` record the option.

Each build tree takes the option on its own configure. The sanitizer trees
read the paths of `build/host/CMakeCache.txt` only for the sysroots and
raylib, so a worktree passes `-DANTI_DEPS_DIR` to the `asan` and `ubsan`
configure as well.

## Test

`deps_dir` (`tests/run_deps_dir.cmake`) copies the sources into its work
directory, where no `build/deps` exists, and configures them with
`-DANTI_DEPS_DIR` set to the downloads of its own tree. It fails when the copy
gets a `build/deps`, when the configure prints a `download` line, or when the
cache names a clang, LLVM, sysroot or raylib directory outside the given one.
It then builds the copy.

Before the fix it failed: the configure downloaded the LLVM tools and clang
into the copy (`build/drive/logs/deps-red-test.log`). After it, it passes in
about 17 seconds (`build/drive/logs/deps-green-test.log`). The first full run
failed `raw_output`, which asks every captured `execute_process` of a test
script for `ENCODING NONE`. The two calls of the new script now pass it.
