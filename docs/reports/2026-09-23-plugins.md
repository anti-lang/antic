# Plugins

The "Plugins" section of `docs/anti-language-additions.md` is built. A library
built with `antic --lib shared --no-runtime` carries what it provides. A host
loads it, asks it for an interface and closes it. The two providers of the
manifest take a provider from one. The development Mac passes 759 of 759 tests,
and the ASan and the UBSan builds pass 758 each, without `no_paths`. Both
sanitizer suites ran before the push. The VMs did not run.

## What was done

1. `5a37f8c`. `provides Interface as Class;` at module level. The parser reads
   the interface as one dotted path, so an alias and a whole module path both
   name it. The checker refuses an interface that is not abstract, a missing
   class and an abstract class. It refuses a singleton, a class that neither
   inherits the interface nor implements it, and two lines for one interface.
   The class record carries one entry per line, and the library file carries
   them from format version 49.

2. `4254856`. `--no-runtime`, with `--lib shared`, writes a plugin: the object
   of its own module alone, linked without the runtime and without the standard
   library, with every name it uses left to the loader. The pass over the whole
   program writes `anti_rt_provides` for it. A program that injects an
   interface or calls the loader is a host: its assembly makes every name
   global and its link passes `-export_dynamic`. antic writes
   `anti-plugins.toml` beside a plugin.

3. `1f7ac77`. `rt/plugin.c` opens a library and checks it against the host.
   `instance`, `supports` and `unload` are there, and `rt/loaded.c` holds the
   open libraries and the two hooks that count their objects.

4. `a6f841c`. `anti.plugin` with `Library`, `load`, `live` and `unload`. The
   compiler carries `lib.instance(I)` and `lib.supports(I, "f")`, each of which
   names an interface where a value stands.

5. `b8e796a`. `"plugin:path"` and `"discover"` of the `[inject]` table, the
   digest check of discovery, and the run-time replacement of `[injections]`
   and `--anti.inject`.

6. `3c8e59f`. `tests/plugin` with an interface, a library that provides it and
   three programs, and two error listings.

7. `a5e2e75`, `7af40f4`, `bfc739f`. The decisions, the notes, `--closed` on
   both halves, and the slot of a library that is loaded twice.

## What failed and how it was fixed

- `ld64.lld` does not implement `-keep_private_externs`, so the runtime's
  symbols could not be exported from a host that was compiled with hidden
  visibility. The runtime now carries no hidden visibility, and the exported
  surface of a shared library for C is pinned by the link instead: an
  `-exported_symbols_list` on macOS, `--exclude-libs ALL` on Linux and the
  `.def` file it already wrote on Windows. `nm -gU` on the shared library of
  `clib_shared` shows its six export functions and `anti_licenses`.

- The first `lib.instance(I)` passed 0 for the descriptor. The case for the new
  expression stood in `lower_address`, which lowers an aggregate, and not in
  `lower_expr_value`, which lowers a pointer.

- The first thunk of a replacement read a register that nothing set. A load
  from a global takes the address the `ir_addr` of that global gives.

- The index of a plugin listed no interface, and a host that injects exported
  nothing. Both read the class records after the optimizer, which drops them.
  Both now read them before it, and the optimizer frees the two lists a record
  owns.

- `windows.h` defines `interface`, so the field of the table that holds the
  path of one is named `path`.

## The provisional entries

`docs/decisions.md` gains a "Plugins" section with one settled entry and
nineteen `[provisional]` ones. The ones worth a second look:

- A plugin brings no constructor. The loader registers the classes the table
  carries, so `reflect.new` finds a class of a library by name.
- `load` checks the runtime version exactly. It checks that every interface
  descriptor lies in the host's image. The hash chain of "Versions" is not
  built, nor the check that no field was added, nor the stub for a
  reflection-reached slot. All three belong to that section.
- The runtime carries no hidden visibility, as above.
- A program loads a library where it is linked dynamically, which is a macOS
  host today. A Linux program of this runtime archive is static against musl.
  A Windows DLL resolves nothing without an import library of its host.
  `--no-runtime` writes a library for every target, and `plugin_host` runs on a
  macOS host alone.
- Discovery searches the directories of the `plugins` key and nothing else. No
  library ships with Anti yet, and the runtime holds no path of the install.
- antic writes `anti-plugins.toml`, which the specification gives to `anti
  build --lib shared`, because that command is not built.

## Questions for Eddie

1. A Linux program cannot load a library, because it is linked statically
   against musl. Should a program that hosts a plugin link dynamically on
   Linux, and against which C library?
2. Windows needs an import library of the host for a DLL to resolve against.
   Is that worth building, or do plugins stay a Unix feature for now?
3. "Versions" is the section that follows "Plugins". Its hash chain and its
   field check are the rest of what a load should compare. Is that the next
   step?
