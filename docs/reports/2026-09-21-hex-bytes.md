# The hex byte literal `x"..."`

The task: `x"..."` from "Small items, round three" of
`docs/anti-language-additions.md`, the prefix set so far `r b br f x` in one
table, `rf` waiting for interpolation, with tests. Built in `425a382`.

## What changed

- `src/lexer.c` reads every string prefix from one table, `string_prefixes`,
  with the literal without a prefix as its empty entry. `string_start` finds
  the entry at a position, and `string` reads the content by the entry's form.
  The old `starts_string` and the `r` and `b` flags are gone.
- `x"00 AB CC"` is a byte string token, so the parser, the checker and the
  back end take it as they take `b"..."`, as a `[]byte`. Whitespace between
  any two digits is ignored, and digits take either case.
- An odd digit count is reported at the unpaired digit, and a character that
  is no hex digit at the first one:
  `` odd digit count in `x"..."` at column 18 ``,
  `` non-hex character `G` in `x"..."` at column 13 ``. `x#"..."#` is refused
  with `` `x"..."` takes no hash delimiters ``.
- `f` stands in the table, and `f"..."` is refused with
  `` `f"..."` is not built yet `` until interpolation is built. `rf` and the
  refusal of `fr` come with interpolation, as the task says.
- `docs/decisions.md` names `x"..."` under "Core language" and "Lexical rules"
  and holds the new section "String prefixes". `docs/anti-syntax-overview.md`
  drops `x"..."` from "Not built yet". `docs/notes/lexer.md` describes the
  table. `CLAUDE.md` carries the new test counts.

## Tests

- `tests/unit/test_lexer.c`: the values of four literals, the prefix set
  (`rb`, `u`, `hex`, `xr` and `bx` stay identifiers before a quote), each
  error with its position, and one report per literal.
- `program_hex_bytes` and its macOS x86_64 twin run
  `tests/programs/hex_bytes.anti`, which prints the bytes of five literals
  and compares one with the escapes of `b"..."`.
- `listing_error_hex_bytes` compiles `tests/errors/hex_bytes.anti` and
  compares the four messages with `tests/errors/hex_bytes.err`.
- `tests/emit-identity/programs.sha256` gained the six digests of the new
  program, written on the Mac. No other digest changed.

## What failed

- The first run of the new unit tests crashed the `unit` binary. Before the
  change `x"00"` lexed as an identifier and a string, and the test helper
  compared the bytes of the identifier. The build of the lexer turned it green.
- The docs-style checker refused `x"..."` without backticks in C comments as
  an ellipsis, and a sentence of 27 words that stood in `test_lexer.c` before.
  Both were rewritten.

## Provisional entries

Under "String prefixes" in `docs/decisions.md`:

- `f"..."` is refused as not built until interpolation is built.
- Whitespace in `x"..."` is a space, a tab, a CR or an LF, ignored between
  any two digits, and a digit takes either case.
- The positions and texts of the two errors and of the refusal of hashes.
  The column in the message is the file column of the digit or character.
