## What failed, and the fix

- anti-linux did not build (`vmc-linux-host-build.log`). The runtime's
  `src/rt/signal.h` hid the header of C on the include path of the unit
  tests, and musl declared no `signal`. The Mac took it from another
  header. The header is `signals.h` now, and `header_names` refuses a
  header of ours named like one a source includes with `<>` (`5c1faebc`).
- anti-windows did not build: `name_in` of `ast_dump.c` took an enum as
  `unsigned`, and an enum is `int` under the Microsoft ABI. A build compiles
  antic for its own host alone. `host_sources_<host>` compiles every source
  of antic and anti for the two Linux and the two Windows hosts with the
  options of a package. It failed on the Mac before the fix.
  `tools/host-compile.cmake` holds those options, which
  `tools/pack-anti.cmake` takes from it (`2420b96e`).
- `test_plugin_table.c` called `fopen` and `strncat`, which the Microsoft
  CRT marks deprecated. It opens through `anti_rt_file_open` and appends
  with a bounded `snprintf` (`9e812b9a`). The red test is the Windows build.
- `trace_forged` ended with `0xc0000409` on Windows, open since fix step
  26. `StackTrace.symbolize` kept its names, from `malloc`, in an `own`
  field. `delete(read, from)` gave them to `LibcAllocator`, whose
  `_aligned_free` stops the program. `std_trace_symbolize_from` counts a
  block given back to an allocator that never lent it, and printed 1
  before the fix. The names are a transient record that `destruct` frees
  (`79a75fb2`). The object is 40 bytes, so the emit-identity manifest was
  written again on the Mac (`d0cd81c9`).
- `fmt_canonical` passed 671 paths, 39386 characters, to one call, past
  the 32767 of a Windows command line. It checks batches of 8000
  characters (`3f14ec6d`). A damaged file in a late batch still fails it.
- `memory_checks` compiled its checked build for the host, which a
  windows-arm64 host refuses before the skip. That build takes
  windows-x86_64 there (`804407bb`). `raw_output` found that my new
  script read clang's output without `ENCODING NONE`, fixed in the same
  commit.
- `deps_dir` failed once because I ran the Windows suite outside
  `vcvarsall.bat`. Run as `test.cmd` runs it, it passes.

`[provisional]` added: the names of `t.symbolize()` are memory the trace

entry on `symbolize`. `docs/notes/hosts-and-harness.md` holds the two

## Questions for Eddie

- **The Linux link of `--memory-checks`.** It has never run before, as
  `2026-09-27-add5-memcheck.md` noted. The AddressSanitizer runtime calls
  `_Unwind_Backtrace` and `_Unwind_GetIP`, and no unwinder stands in the
  glibc sysroot or the runtime archive (`vmc-linux-host-1.log`). Option
  (a) adds `libgcc-s1` of Ubuntu 22.04 to `GLIBC_PACKAGES`, a GCC part
  with its runtime exception that every package then carries. Option (b)
  is a shim that takes both calls from `libgcc_s.so.1` of the machine
  through `dlopen`. Option (c) builds LLVM's libunwind into the runtime
  archive. Antic writes no
  CFI on ELF, so the slow unwinder of the report stops at the first Anti
  frame under (a), (b) and (c) alike. The report then needs
  `fast_unwind_on_fatal=1` in the options hook as well.
- **The stack of a 1024-deep tree.** `unit_modules` overflows the 8 MB of
  Linux under UBSan. Its `deep_chain` writes a chain 1040 deep for the
  reader to refuse. At `-O0` under ASan and UBSan, `io_expr_body` and
  `walk_at` take about 8 KB each, so the write needs 8 to 10 MB. The Mac
  passes only because ctest gives its children a 64 MB stack, and the
  binary run by hand overflows there too. Should antic run its work on a
  thread with a stack of its own size, the unit tests give the deep cases
  one, or `ANTL_TREE_DEPTH_MAX` come down to the 512 that source reaches?
