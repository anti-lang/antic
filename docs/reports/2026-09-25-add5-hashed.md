# The hashed maps and sets

The step builds `Map<K, V>` and `HashMap<K, V>` in `anti.collection.map` and
`Set<T>`, `HashSet<T>` and `BitSet` in `anti.collection.set`. Four points of
the round need a change outside the two modules and stand under "Blocked".

## What was done

- `src/std/anti/collection/map.anti`: the two tables `EntryTable<E>` and
  `SlotTable<E>`, `Map` and `HashMap` with every operation of "Maps", their
  iterators, `to_text`, `serialize` and a copy for `dup`. `HashMap` walks in a
  new random order on every walk, and `serialize` sorts it by key for the
  built-in types that have `<`.
- `src/std/anti/collection/set.anti`: `Set` and `HashSet` on those tables, and
  `BitSet` over words of bits.
- Tests: `std_map`, `std_hash_map`, `std_set` and `std_hash_set` in release,
  and their `_dev` runs, which need the new fixtures `dev_object_collection_map`
  and `dev_object_collection_set`. Each runs every operation, the insertion
  order after removals, `dup`, the room from a counting allocator and 20000
  steps of churn over keys and values that own memory, which end with no block
  alive. The checks `map_changed` and `set_changed` of `run_checks.cmake` stop
  a dev build whose walk sees the collection change.
- `anti_check` counts 25 files of the standard library instead of 23.
- Commits: `598b8ae` the maps, `d6ff196` the sets, then the walking order from
  the system, the decisions and the count of `anti check`.

## What failed and how it was fixed

- A tuple literal of an `own` parameter, `(dup(k), v)`, compiled in a generic
  copy and tore `v` down at the end of the function, since the concrete form
  refuses it. The tables now give the new entry in place and the map writes
  its parts, `e.0 = dup(k)` and `e.1 = v`.
- The text order of moves refused a second `e.1 = v` on another branch.
  `entry_for` gives the old or the new entry, and one assignment follows.
- `rebuild(0)` and `resize(0)` of an emptied table stopped on a pointer that
  was `none`. Both now give back the old block and return.
- A dev build refused `r as int` of a random `u64`. The walk masks first.
- The `to_text` of `Collection<T>` compares each place with `first_place()`,
  which starts a new random walk in a hashed table. `HashSet` writes its own.
- Importing `anti.reflect` for its type ids made a dev link need its object.
  The map keeps the ids it reads as constants.
- The walk of a `HashMap` first drew its order from the hash seed, which
  `--anti.hash_seed` fixes. Each table now draws a number from the system.
- `fmt_canonical` and `anti_check` failed once each before their commits.

## Defects of the compiler the tests pass around

- A class value made at a parameter without `own`, `m.get(Id.of(1))`, is never
  torn down. The tests put such keys in locals.
- `if let x = o`, `let x = o else { }` and `o ?? d` over a local `?T` of an
  owning type tear the value down twice. A call on the right works.
- In a function that is not generic, `e.1 = v` through a pointer with `own v`
  tears `v` down at the end of the function.
- ARM64: an `f32` part of a tuple element of 8 bytes reads with
  `ldr s0, [x9, x10, lsl #3]`, which llvm-mc refuses. `HashMap<i32, f32>`
  shows it.
- `~other.word(i)` gives `` unknown name `BitSet.word` ``, and
  `map.Map<str, int>.new()` cannot infer `K`. A direct import works.

## Provisional decisions

All in `docs/decisions-hashed.md`: the two tables, the block of a `Map`, the
probing and growth of a `HashMap`, the walking order, the copy of the key in
`set` and `add`, keys that never change in place, `read`, `update` and `modify`
giving `bool`, the iterators, the forms of `to_text` and `serialize`, the type
ids, `==` in order, the set operations by value, `dup`, the rules of `BitSet`
and the missing `deserialize`.

## Blocked

- `==` of a generic class does not reach a program from a library file, so
  `Map` and `Set` have `==` in their modules that no test can call. The fix
  lies in `src/antic/sema_expr.c`.
- One module gives `==` to one generic class only, so `HashMap` and `HashSet`
  have none. Which form gives the second class its hook?
- `union` is a keyword, so `s.union(o)` does not parse. Should the parser take
  it as a member name, or does the function take another name?
- `serialize` of a `HashMap` writes a key of a struct, a class or a variant
  with `operator fn lt` in slot order. A generic cannot ask whether its
  argument has `lt`. This needs a change in `src/antic/` or a decision.
