## Questions answered from the code

- Does `deserialize` of a collection compile? `Object.deserialize` compiles on a `List`, and gives `none` for the JSON array that `serialize` writes, by the entry on its result in `docs/decisions.md`. The page shows it.
- Does a plain pointer stay alive after `push`? No. `moves_at_call` of `src/antic/sema_value.c` moves a value that holds a pointer into an `own` parameter, so a second `push(k)` of a `*P` is refused by `use-after-free`. R081 says that such a parameter owns the pointer value alone, and E2 that an `own` parameter moves its argument. The two agree, and the page tells the reader to keep a second pointer.
- Is a struct with `operator fn eq` and no `operator fn hash` refused? No rule refuses it. Decision 27 of "Decisions of 2026-10-11" refuses the pair for a class alone. The page names it as a pitfall.
- Does `antic -c` write the same library file for every target? Yes, 825 bytes for macos-arm64, linux-x86_64 and windows-arm64, byte for byte.
- Is the link of a Windows library reproducible? Two builds of `geometry.dll` and `geometry.lib` for windows-x86_64 compare equal.
- Does `anti bind --clang` in a tree need the runtime? Yes, `--runtime`, for the sysroot whose headers clang reads.
