# The answers of 2026-11-06 and anti.math

The session recorded Eddie's answers of 2026-11-06, built the refusal of
`publish` in every form and built `anti.math` over the libm of musl in the
runtime. `anti.graphics` is approved and not built.

## What changed

- `8e126382` records "Answers of 2026-11-06" in `docs/decisions.md`, the
  line of the feature freeze, the rules of both modules in "Standard
  interfaces" of `docs/anti-language-additions.md` and the overview. The
  two notes are the design notes of their modules.
- `d4fd26cc` refuses a `[package]` that names `publish` without `name` in
  any form, the empty string, an array, a table and an empty `[]` or
  `[package.publish]` among them. A `publish` that is no string is refused
  with `name` as well. `src/rt/toml.c` records whether a value stood in
  quotes and the path of every empty array and table, and
  `anti_rt_toml_shape` gives the shape at a path. An empty value adds no
  key, so every reader that walks the keys reads the document as before.
- `d2d9d960` builds `anti.math` and the constraint `Float`.
  - `src/std/anti/math.anti` holds the 30 functions, the five helpers of
    raymath and the five constants. Each function is generic over `Float`
    and takes the `f32` or the `f64` function of the runtime by
    `size_of(T)`.
  - The checker gives `Float` the hooks of `Number` and `eq`, marks the
    closed set with the bit `TYPE_PARAM_FLOAT` of the hooks, refuses any
    other type and lets `as` convert a value of the parameter. The format
    of the library file stays at 93.
  - `src/native/libm.cmake` fetches the musl source of
    `tools/sysroot-pins` through `antic_get_source` and compiles 83 files
    of `src/math/` into anti_rt at every level of all eight runtime
    targets, in its objects, both bitcodes and the runtime of the fault
    tests, with musl's own flags and `ANTIC_FP_OPTIONS`.
  - `src/native/libm-names.h` gives every symbol the prefix
    `anti_rt_libm_`. LLVM knows no such name, so no call is folded with
    the libm of the host and none binds to the libm of a system.
  - `src/rt/libm.c` holds the nine exact functions through the
    elementwise built-ins of clang. The four roundings call musl at
    x86-64-v1, where LLVM would call `floorf` of the system.
  - The notice of a program of `anti.math` names musl on every target.
  - `musl.txt` and the line of musl in `licenses/sources.txt` stood in the
    runtime archive already, from the Linux sysroots.

## Tests

- `std_math`, `std_math_dev` and `std_math_memory_checks` hold the
  reference values of every function in `f32` and `f64`, 355 lines. Each
  result agrees with the libm of the Mac within one unit in the last
  place, checked by hand before the file was pinned.
- `std_math_macos-x86_64` runs the same program at `v1` under Rosetta
  against the same file, so both processors give the same bits.
- `std_math_constant` in the same four forms compares a call on a constant
  with one on a value of run time for nine functions.
- `math_link_<target>` links the program for all six targets and at `v1`
  for both x86_64 targets. It refuses an executable that takes a function
  of a libm of the system.
- `libm_symbols` reads every symbol of the libm and of `libm.o` in the
  runtime of every target and level.
- `runtime_fp_contract` takes `anti_rt_libm`, its two bitcodes and its
  runtime of the fault tests. Before the build it failed for all four.
- `license_notice_native` finds musl in the notice of a program of
  `anti.math` for every target, and none on macOS and Windows without it.
- `matrix/generics_float_takes_f32_and_f64` and three refusals: an `int`, a
  struct with the hooks of `Number` and `as bool`.
- Eight cases `anti_build_message_manifest_publish_*` and `value_shapes`
  of `unit_toml`. Seven cases failed before the change, and the case of
  the empty string came after it.
- The digest of `return42` for macos-arm64 is written again twice, since
  the reader and then the libm changed the runtime it links.

## Questions for Eddie

1. The constants are `f32`, as raylib's, since `anti.graphics` writes
   `a * math.DEG2RAD` with an `f32` angle. A program of `f64` then writes
   `math.PI as f64`, which loses the digits of an `f64`. Should the module
   carry `f64` constants as well, and under which names?
2. A NaN prints as `nan` in the tests, since x86_64 gives a negative NaN
   for a domain error and ARM64 a positive one. Is a NaN whose sign
   follows the processor acceptable under Q2, or should every function
   give one NaN on every target?
3. The exact functions are one instruction in a release build. In dev
   mode and under `--lto none` each is a call of a function of one
   instruction. Is that enough, or should antic write the intrinsic
   itself?
