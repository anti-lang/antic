# The synchronized collections, second and third run

Step add5-sync of round five. `docs/reports/2026-09-28-add5-sync.md` reports
the first run, which built `SyncList<T>`, `SyncMap<K, V>`, `SyncSet<T>` and
`SyncPool<T>` and stopped on the double free of `Pool`. The second run stopped
on `==` and the hash of the four classes. The third run builds them on the
`sync a, b` of main, and the step is complete.

## Done in the second run

- `b9ea9c5` on main moves an `own` parameter or a local into a literal, so
  `Pool` frees an owning element once. `SyncPool` needed no change.
  `std_sync_pool` takes `get_versioned`, `remove_all`, `remove_first`,
  `remove_one` and `clear` through a `SyncPool<Id>` under the count of live
  blocks and allocations.
- `push` and `set_if_version` of `SyncList` move `x` into the pair they store.

## Done in the third run

- `1c520c4` gives each class `operator fn eq` and `operator fn hash` over
  pointers. Each holds `sync a, b` or `sync a` and compares or hashes the
  elements alone, as the plain collection does. The versions, the clock and
  the allocator are no part of the value, and the hash equals that of the
  plain collection with the same elements.
- `std_sync_equal` checks equal collections whose versions differ, one with
  another element and each with itself, and the hash against the plain
  collection. A dispatched job and the main thread compare the same two
  collections both ways round while another job writes every element back
  unchanged. Every comparison finds them equal. It runs in release and dev
  mode, with a timeout of 120 seconds.
- `docs/decisions-sync.md` records the operators and moves the two findings
  on `==` from open to fixed.

## Failed and fixed

- The operators first read the fields of the class, which a synchronized
  class closes to every function outside it. Private functions of each class
  now read them, since a module operator reaches those.
- The test first dispatched two jobs on one collection. The second job of an
  object in flight does nothing, so its `join` gave 0. The main thread now
  takes one of the two comparisons.
- The first ASan configure ran beside the UBSan configure and read `ld.lld`
  of the shared `build/deps` while the other checked it. Run alone, it passed.
- In the second run, `let (got, version) = p.get_versioned(h) else { }` did
  not parse. The test takes the call result apart with `??`.
