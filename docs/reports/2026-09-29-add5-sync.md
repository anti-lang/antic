## Blocked

The specification gives every collection the `eq` hook, element by element,
and gives a synchronized class the default `==` and hash with the lock left
out. The four classes take that default. It compares the versions, the clock
and the allocator beside the elements, so two `SyncList` values that hold `[1]`
are unequal when one took a `push` and a `pop` first. It also reads the
fields without the hidden lock. An `operator fn eq` of the module, as
`anti.collection.pool` has, receives a byte copy of each operand with its lock,
and waits forever on a copy taken while another thread held it. The fix lies
in `src/antic/`, outside the fence, and needs a decision the documents do not
hold.

## Questions

- Should `==` and `hash` of a synchronized class pass the address of each
  operand, so the module can give the four classes an `==` over the elements
  that takes each lock in turn, as `ConcurrentMap` does?
- Or should the default `==` of a synchronized class take the lock of each
  operand, and the four classes keep their versions out of it?
