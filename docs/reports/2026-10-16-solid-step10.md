`e9b3f5d3` writes the commits into the summary.

- S301. The two walks pass over a base field without a type, as
  `nest_value` does. The empty base stays the mark of a refused base,
  which T096 reads in `sema.c` and `sema_class.c`, so giving the class
  `types_object` was not taken. `error_refused_base_uses` names two
  refused classes by a channel, a `parallel`, an `own` parameter and a
  field default. Before the fix antic ended with a segmentation fault,
  exit 139.
- S302. The walk now compares `f->home` with each level. Every field
  array is made by `types_set_fields`, which sets `home`. No program can
  show the undefined comparison. The new program
  `classes_generic_interface_of_a_base` takes the path `xf` serves: a copy
  converts to a generic interface of its base inside a generic body. With
  `xf` handing back the generic's field, the program crashes. No test
  reached that path before.
- S321. `matrix_values_function_compared_with_a_nullable_function` passes
  in all three modes, `step10-t4.log`.
- M328. The reading of the target marks the checked base for that reading
  alone and restores the mark. The tree and the library file keep no new
  flag. `types_unknown_name_in_the_base_of_an_index_target` gave the
  message twice, and `ownership_own_argument_in_the_base_of_an_index_target`
  was refused with `` `b` was moved into `slots` ``. Both failed before
  the fix, `step10-t5b.log`, and pass after it.
